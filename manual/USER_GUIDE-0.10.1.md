## 1. 先了解：这个插件能做什么

### 1.1 四个部分各管什么

可以把整个系统理解为四个协作部分：DSH 负责运行模型与插件；QQ 桥接负责把允许的 QQ 消息交给模型，并把回复发回去；memvec 负责保存和检索记忆；本插件网页让你查看、核对和管理这些内容。

因此，网页打开不代表 QQ 已连通；QQ 能聊天也不代表记忆服务已启动。总览的启动检查就是用来区分这些情况的。

插件不是完整 QQ 机器人安装器。你仍需准备兼容的 DSH、基础桥接及其 SDK、SnowLuma 和可用 QQ 登录状态。现有安装可以升级；没有基础桥接的新用户，应先完成基础环境配置。

### 1.2 几种内容不要混淆

| 内容 | 通俗解释 | 例子 |
| --- | --- | --- |
| 聊天原文 | 当时说过的话 | 我今天加班，明天再聊 |
| 长期记忆 | 从原话中提取的个人事实 | 我不喜欢香菜 |
| 挂念 | 尚未结束、可能在后续继续聊的事情 | 明天的面试 |
| 待验证认识 | 有依据但可能理解错的暂时猜测 | 也许比较担心准备不充分 |
| 摘要或联想 | 对聊天的压缩整理，或暂时想到的话题 | 最近工作忙；下次可以聊休息安排 |

“模型说它记住了”只是一句回复。要确认实际保存，应到长期记忆页看记录和来源。“想到一个话题”也不等于多了一条真实事实。

### 1.3 v0.10.1 的变化

本版增加成长课堂、省心整理、按内容变化的记忆保留和首次使用向导，改善日常情绪、共享范围及重复调用。六维与可成长自我参考并存，自然表达规则单独保留；后台思考强度分模块设置，聊天配置独立。待确认内容不会因为升级而自动全部通过，归档也不等于记住。

旧用户须按升级指南同步插件、桥接与记忆服务；可成长自我参考按配置启用。详细操作见新增的第21至23章。

## 2. 安装前准备与首次启动

### 2.1 需要准备什么

需要 Node.js 24+、Python 3.10+、兼容的 DSH，以及已能正常工作的 QQ 桥接。提取、查漏和摘要需要模型服务；本地向量检索需要 memvec 及其依赖。首次启动向量模型可能需要联网下载，之后可以使用本机缓存。

从 GitHub Release 下载版本一致的插件包、升级指南和手册。`.tgz` 用于插件安装，`-source.zip` 用于查看和部署源码；不要把 GitHub 自动生成的 Source code 按钮误认为包含全部单独发布附件的安装包。

### 2.2 找到三个真实路径

先记下“插件目录”“QQ 桥接目录”“memvec 实际运行目录”。它们可能不在一起。Windows 中 `~` 表示当前用户目录，例如 `C:\Users\你的用户名`；不要照抄他人的用户名。

常见数据目录是 `~/.dsh/memvec`、`~/.dsh/qq-bridge` 和 `~/.dsh/feiyu-memory-console`。如果你改过位置，以自己的配置和启动检查为准。

### 2.3 新环境检查

在插件解压目录打开 PowerShell，执行：

```powershell
npm run doctor
python -m pip install -r memvec/requirements.txt
npm run start:memvec
```

第一条只检查环境。第二条安装 Python 依赖，必须使用你准备运行 memvec 的 Python 环境。第三条启动记忆服务；关闭这个前台窗口会停止服务。

已有数据库的用户不要随意换路径。如果页面突然变成零条记忆，先排查是不是打开了新的空库，不要立即重新导入或删除旧库。

### 2.4 安装桥接更新

先备份并停止已有桥接，再在插件目录执行：

```powershell
node bridge/install-all.mjs --target "D:\your-dsh\qq-bridge" --check
node bridge/install-all.mjs --target "D:\your-dsh\qq-bridge" --apply
```

示例路径必须换成自己的实际目录。`--check` 只检查，`--apply` 才安装。若提示未知版本、自定义修改或备份校验失败，先保留现场并核对差异，不要反复强制覆盖。安装器不会帮你安装基础 SDK，也不会自动升级独立 memvec 文件。

按当前 DSH 的本地插件入口安装 `.tgz` 或链接实际源码目录。升级过插件后重启 DSH，因为宿主路由在启动时加载。memvec 如果独立运行在别处，还需更新其实际使用的 `server.py`，具体见升级指南。

### 2.5 启动和检查

启动 memvec、DSH 和 QQ 桥接。在 DSH 打开可塑性记忆；默认网页地址是 `http://127.0.0.1:3080/dsh-feiyu-memory/`。若你改过宿主端口，请使用实际地址。

总览应显示当前版本、数据库和服务检查结果。默认记忆服务端口为 9881，桥接控制端口为 3100。不要把服务端口开放到公网。桥接控制接口可能需要鉴权，直接用浏览器访问某个 API 返回未授权，不等于桥接没有启动。

## 3. 十分钟上手

### 3.1 做一次简单验证

1. 在允许的私聊里说：“我喜欢喝豆浆。我不喜欢香菜。”
2. 打开“整理”，查看是否出现该聊天的待处理消息。自动整理有等待和批次条件，不保证每条消息立即入库。
3. 如需立即验证，点该聊天的“整理这格”。它会调用模型，通常包含提取和查漏两个步骤。
4. 查看“消息处理状态与遗漏检查”，确认是在排队、检查、重试，还是已经完成。
5. 打开“长期记忆”，选中对应聊天，分别查看“活着”和“待确认”。事实置信度及判断结果不同，落入的状态也可能不同。
6. 对照原话核对两条记录，尤其检查“不喜欢”有没有变成“喜欢”。

如果没有新增事实，不要只看机器人回复。沿着“有没有入队 → 是否提取 → 是否发现遗漏 → 是否待确认”的顺序排查。

### 3.2 推荐的日常检查习惯

平时正常聊天即可。偶尔查看待确认内容、失败重试和模型用量；遇到错误，先核对来源，再决定改正文、归档或删除。对于重要的偏好、承诺或待办，用完整、明确的一句话说明，比只说“还是照旧”更容易准确保存。

## 4. 总览与功能开关

总览用于快速确认运行情况，包括启动检查、记忆数量、待处理队列和功能入口。顶部版本来自实际加载的后端，不是只写在网页上的固定文案。

如果更新后仍显示旧版，先重启 DSH并刷新网页，再核对加载的插件目录。仅刷新无法重载所有后端路由。

“跨聊天记忆共享”与“空闲联想”是两件事。开启共享后，普通事实和旧 global 经过隐私审核即可跨聊天使用，不用逐条确认；私密、不确定、未确认或到期内容不自动共享。首次遇到相关但未审核的内容会产生“共享隐私判断”用量，之后相同版本复用。联想试验仍从主人当前私聊的记忆出发。

在已确认记忆的“共享范围”查看判断结果，可标记私密、设为普通、重新自动判断，以及禁止或单独授权具体聊天。私密设置优先于目标授权，内容变化会使旧放行失效。关闭共享后同聊天召回继续；撤销不能收回已发送内容。管理员明确询问其他聊天时，可提供角色确实参与过的安全摘要片段，她可以选择是否讲述；此问意识别复用已开启的连续事件理解。情绪的对象区分、迁移和完整操作见[记忆与情绪的范围](../docs/memory-emotion-isolation.md)。

## 5. 长期记忆：查看、创建和维护

### 5.1 如何找到一条记录

进入“长期记忆”，先选择聊天，再选择状态、层级和排序。输入文字可做文字筛选；“语义找”用于找意思相近的内容。记录卡片中的原话、来源时间和说话人，是判断是否准确的重要依据。

| 状态 | 含义 | 通常怎么处理 |
| --- | --- | --- |
| 活着（active） | 当前有效的已确认记忆 | 检查来源；必要时编辑、归档或删除 |
| 待确认（candidate） | 尚待核对，可能有冲突或不确定 | 对照原话确认，不能当作已采纳的事实 |
| 已归档（archived） | 暂不参与正常有效记忆使用 | 需要时恢复，恢复也要核对冲突 |
| 被取代（superseded） | 已有另一条事实代替它 | 查看替代关系，不应只因记录较新就覆盖 |
| 已删除（deleted） | 软删除状态 | 若页面支持可恢复；不等于清除所有备份 |
| 已完成（completed） | 已完成的待办 | 保留完成记录，不继续作为未完成任务 |

### 5.2 层级与重要度

“普通”会受到遗忘、到期与整理规则影响；“核心”用于希望长期保留的事实；“待办”用于做完前需要记住的任务。层级和重要度影响保存或检索策略，不保证模型每次回复都提到它。

自动提取的计划和经历通常有到期时间。若这是长期有效的承诺，请核对层级和有效期，不要默认所有“记住”都会永久保存。

### 5.3 手动新增和编辑

点击新增入口，选择“记到哪”，写清事实正文，按需要设置层级、重要度和说话人。正文最多 500 字；建议一条记录只放一个清楚的事实。

“事实键”用于分类，不是同键自动覆盖规则。不要为了让一条新事实替换旧事实而随意复用键；应走核对和明确选择流程。群聊记录尤其要确认说话人，避免把甲的偏好记到乙身上。

编辑前先展开来源。改成的内容应有真实依据，不能把猜测直接改成事实。无法确定时先归档或保留待核对，比写一个看似正确的结论更稳妥。

### 5.4 归档、删除、恢复和导出

暂时不想使用一条记忆，可归档；确定不应保留为当前记忆，可删除。恢复时系统仍要检查现有事实，不能用恢复绕过冲突核对。导出适合阅读和转移记录，不等于完整应用备份。

部分操作会在“整理 → 操作记录”中提供撤销。后来有其他修改时，为防止覆盖新数据，撤销可能被拒绝。没有撤销入口的操作不要假定可以一键恢复。

## 6. 冲突核对：确认与恢复

### 6.1 哪些情况能同时成立

| 两条信息 | 应怎样理解 |
| --- | --- |
| 不喜欢煎饼；喜欢小笼包 | 对象不同，可以共存 |
| 工作日喝咖啡；周末喝茶 | 条件不同，可以共存 |
| 喜欢茶；只喝无糖茶 | 可能是补充，需要保留限制条件 |
| 以前喜欢咖啡；现在不喜欢了 | 明确改口，可能替换旧偏好 |
| 喜欢咖啡；不喜欢咖啡 | 若时间和条件不清，应先核对 |

同属一种分类、文字相似或入库时间较新，都不足以证明应该替换。检查对象、肯否、适用条件、时间和说话人。

### 6.2 点击确认后发生什么

系统取同一聊天、同一主体的有效已确认事实，每批最多八条交给模型核对。超过八条会继续下一批，网页显示“历史已复核 X/Y 条”。进度保存在数据库中，失败后可再次点击继续。

“停止后续检查”停止后面的批次，不保证能取消已经发出的模型请求；已完成批次会保留。只有需要检查的历史完成后，才进入确认或冲突选择。普通检索更新阅读次数不会重置进度；事实正文、状态或来源发生相关变化时，需要重新核对。

### 6.3 弹窗中的选择

出现很多旧记忆，不代表它们只能有一条是真的。系统分别展示“明确矛盾”和折叠的“关系尚不确定”；相同事实和可以共存的内容不作为必须二选一的冲突。

例如“不喜欢煎饼”和“喜欢小笼包”都是真的时，不需要删掉其中一条。先核对候选原话，再选择默认项“确认这条，并保留全部已有记忆”。

- **暂不处理**：关闭弹窗，先不作决定。
- **归档这条候选，保留已有事实**：候选移入归档，已有事实保留；恢复操作对应“暂不恢复，保持已归档/已删状态”。
- **确认这条，并保留全部已有记忆**：只确认当前候选，全部已有事实保持不变；恢复时同样保留其他有效事实。
- **仅替换 N 条明确矛盾**：只在存在明确矛盾时提供。逐条核对来源，替换这些记录，其他不确定、重复和共存记录都保留。

如果没有明确矛盾，不提供替换选项。即使旧客户端直接提交替换请求，服务端也不能据此覆盖不确定事实。后续想撤销时，可到操作记录查看支持撤销的记录；若数据已变更，系统可能要求先重新核对。

若提示历史尚未检查完或模型暂不可用，保留现场后重试。“无法判定”不等于“确定矛盾”，也不等于“确定没有矛盾”。

### 6.4 跨聊天与旧 global 记录

本次核对不会扫描其他聊天的人，也不会把跨聊天共享开关当成修改权限。旧 global 的普通内容可经隐私审核共享；本次事实纠错仍需要核对原始来源，不能把共享权限当成修改事实的依据。

### 6.5 一直不确认，会丢失吗？

不会因为等待时间长而自动删除候选。它仍保存在数据库的“待确认”中，但不作为已确认事实进入正常记忆检索。手动删除、归档或记录原本有有效期，是不同情况。到期的记录不会因为点击确认而自动延长有效期。

| 操作 | 候选的结果 | 已有事实 |
| --- | --- | --- |
| 暂不处理 | 仍为待确认，可以以后处理 | 保留 |
| 归档这条候选，保留已有事实 | 移入归档，不再作为待确认 | 保留 |
| 确认这条，并保留全部已有记忆 | 成为已确认记录；仍遵守原有效期 | 保留 |

### 6.6 让模型自动核对

在“长期记忆 → 待确认”勾选“自动核对待确认记忆”。默认关闭，仅处理配置中的主人私聊候选，不扩大跨聊天共享。

它会先检查来源和期限，逐批核对全部相关旧事实，再让模型核对候选是否由原话明确支持。原话明确、归属明确、不是引用/玩笑/假设、没有未解决冲突且版本没有变化，才自动确认。模型自报的高把握度仅是一个门槛，不是准确率保证。

存在矛盾、关系不确定、缺少完整原话、原话超过 500 字、事实到期或语义含糊时，会保留待确认并显示原因。不会自动替换旧事实，也不会把“待验证认识”或空闲联想升级为事实。不确定的原记录不会反复付费重查；内容或来源变更后才会重新进入核对。

每分钟最多处理一条候选或一批历史；一批历史最多八条，进度保存，后续继续。按钮“检查下一条”可以手动触发一次；不设置每日次数硬上限，但不会同时堆积自动任务。

关闭网页后，只要 DSH 仍运行且开关开启，自动核对仍会继续。关闭开关停止后续提交；已经提交完成的操作不会因此自动撤销。服务失败会退避重试。自动确认可在“整理 → 操作记录”查看和撤销；若记录又发生变化，撤销可能被拒绝，需要重新核对。

花费页中原话判断记为“候选核对”，历史关系判断记为“事实复核”。模型可能误判，界面保留人工入口。

## 7. 整理队列与独立遗漏检查

### 7.1 一条消息怎样变成记忆

流程是：允许的消息进入队列 → 提取模型逐事实整理 → 完成声明交给独立调用核查 → 保存有效条目 → 完整处理的消息移出队列。中间失败、遗漏或不确定的消息会保留，以便继续处理。

独立检查使用新的无工具调用，但通常仍是同一模型服务，不是人类审核，也不一定是另一种模型。两个调用仍可能犯相同错误。

### 7.2 哪些聊天会进入队列

允许参与的私聊不再要求出现“喜欢”“记住”等固定词。群聊默认 addressed 策略只处理 @ 或回复机器人的消息；semantic 策略可处理允许群中的普通发言，旧 signals 配置等同 semantic。off 关闭群聊提取。

会话授权、总开关、机器人过滤和命令过滤仍生效。不在授权范围的聊天不会因为一句话很重要就自动入队。暂停自动整理时，新的消息不再进入该整理队列，已有队列保留；这期间的消息不会在重新开启后自动全部补回。

### 7.3 手动整理和额度

在“整理”找到对应聊天，点“整理这格”。每次最多选择 12 条消息，并受文本预算约束；单批输出也有限，多事实消息可能分几次完成。操作只针对选中的聊天，不会因为它空了而改动别的聊天。

手动整理可以越过自动批次额度和重试等待，但仍要满足会话范围、服务可用及任务不忙等条件。没有事实的闲聊产生零条记录也正常。

新配置总额度默认不限，`0` 表示不限；群聊默认每天最多 20 个成功整理批次。旧配置原样保留。成功批次可能包含两次模型调用，失败请求也可能产生费用，因此额度不是严格的 token 或金额上限。

### 7.4 看懂消息处理状态

在“整理”展开“查看消息处理状态与遗漏检查”。

| 状态 | 表示什么 | 建议动作 |
| --- | --- | --- |
| 待处理 | 消息还在队列 | 等待，或手动整理 |
| 正在提取 | 正在请求整理模型 | 等待，避免连续重复点击 |
| 正在检查遗漏 | 正在对照原话查漏 | 等待检查完成 |
| 发现遗漏 / 继续处理 | 有未完整处理的内容 | 查看待补齐原话，再等下一轮 |
| 待复核 | 归属或完整性等仍不确定 | 对照原话，必要时人工整理 |
| 失败重试 | 模型、格式或存储环节失败 | 看原因，修好服务后重试 |
| 已检查，无新增有效事实 | 检查后没有新增可保存事实 | 闲聊可能正常；重要内容可人工核对 |
| 提取时已记住 | 处理当时有有效记忆 | 到长期记忆页看当前状态 |
| 提取时待确认 | 当时生成了候选 | 去长期记忆的待确认列表核对 |
| 队列容量限制 | 达到配置容量，未继续整理 | 重要内容按原话手动补录 |

处理记录最多显示近期 500 条；不是完整聊天档案。后来确认、删除或过期不会把旧处理回执变成实时事实状态。

### 7.5 为什么还有等待

失败按 30 秒到 30 分钟逐步退避，避免不断重试；不确定结果也会延迟再检查。群聊若长期低产出，原有策略可暂停自动整理七天，页面会显示暂停时间。超过 12000 字的消息保留待拆分，不会阻塞其他聊天的正常整理。

发现过去某条消息漏记，并不意味着新版会自动修复它。可以重新完整说明事实，或在对应聊天范围手动新增，避免把第三人的话当作自己的事实。

## 8. 搜索、记忆图和回复证据

### 8.1 文字筛选与语义找

文字筛选适合知道具体关键词时使用；语义找适合表达相近但用词不同时使用。例如记忆里是“喜欢雨声”，你可以用“下雨时喜欢听什么”查找相关记录。相关分数是排序依据，不是事实正确率。

语义找主要使用本地向量模型，不单独请求聊天模型生成答案。第一次使用仍可能依赖本地模型下载及加载。

### 8.2 查看检索依据与来源

展开证据，可看到原话、来源、范围和检索信息。控制台检索属于预览，不能据此推断“刚刚那句 QQ 回复肯定用了这条”。实际回复使用情况要看会话上下文中的对应回合记录。

回合可能显示成功、失败、部分发送或状态不明。发送不明时不要把它当作已送达；“本轮不相关”的反馈绑定实际回合，不会自动删除那条记忆。

### 8.3 记忆图

记忆图把记录画成节点，把系统识别的关系画成连线。可缩放、拖动、按范围或层级筛选，并切换视图。它适合发现关联和查看分布，不应把一条连线当成真实因果关系证明。

大库会受到加载上限或分页影响，看不到某个节点不一定代表记录被删除，应回长期记忆页搜索。

## 9. 聊天原文与摘要

会话上下文入口用于查看某个聊天的原文、摘要和相关回合信息。具体入口取决于宿主的会话面板；它不一定是主页面顶部的独立标签。

原文保存说过什么，摘要把一段对话压缩成较短内容。摘要不是完整录音式存档，可能省略细节或产生误解。重要事实仍应保留可核对的原话。

需要整理时，在该会话上下文页面使用摘要入口。生成摘要会调用模型；删除错误摘要只处理摘要层，不会自动删除原文、长期记忆或撤回已发送回复。以后生成的新摘要也仍要核对。

原文层有保留条数和文本预算，长消息与过旧内容可能不完整。不能把“当前上下文没显示”直接理解为“整套系统从未保存过”。如果涉及重要纠错，提供原句、说话人和时间会更有帮助。

## 10. 轻量记忆、日记和情景记录

### 10.1 轻量记忆

“轻量记忆”包含正在聊的话题、想说但还没说的话、群友印象等。先选聊天，再查看或编辑对应内容。可以新增话题、补充尚未问出的问题，或移除过时印象。

这些内容服务于聊天连贯性，不等于长期已确认事实。添加一句“想说的话”不会立即向 QQ 发出消息，也不保证下一次一定说到。

新版还显示两类内容：

- **已确认的信息**：直接读取所选聊天里有效、未过期、未被替代的长期记忆。私聊只显示该对象的信息；群聊保留每条的真实主体。先显示六条，可展开更多，最多读取三十条。不是把私人资料复制到群里。点来源核对原话，需要改错时到长期记忆处理。
- **自动近期便签**：记忆整理时顺便记录短期计划、正在做的事等。要求当前发言者明确自述、准确原话与足够置信度，排除敏感、引用、假设和不确定内容。通常保留 1 至 24 小时，从原消息时间计算；重复原话不续期。明确完成会结束，也可手动移除，记录保留在处理审计中。不会自动成为已确认长期事实。

便签沿用原有整理开关、聊天范围和批次；新消息通常在空闲约 90 秒或积累到批次后整理。没有便签可能是没有明确短期事项、证据不够、已到期或该聊天未入队。处理记录可查看检查、跳过和失败原因。没有历史回填；原有手动话题和工具写入内容仍保留。

### 10.2 公开日记

在“日记”选择公开本和日期，阅读当天记录。页面提供的编辑、补页等操作会影响日记正文。修改后可查看操作记录，确认是否提供撤销。

日记是整理和生成结果，不能仅凭日记一句话就判定你真实说过。涉及偏好或承诺时，仍应核对聊天原文。

### 10.3 私密日记

选择私密本后按页面要求解锁。当前支持查看与补页，不支持像公开本一样任意编辑全部正文。补页可能调用模型。

私密本使用加密文件，但本机管理员和持有解锁材料的人仍可能读取；不要把它当成独立于本机权限的保险箱。私密日记不会因为能在控制台查看，就自动变成所有聊天可共享的记忆。

### 10.4 情景记录

在情绪相关页面查看情景记录，包括发生的事件、系统解释、情绪、行动和结果。可以按入口补充结果或删除不合适的记录。

“解释”和“结果”可能来自模型或启发式整理，不是客观事实认证。澄清误会后，关联解释可能标记撤回，但已经发送的消息和独立日记不会自动消失。

## 11. 性格与情绪系统

“情绪”“性格”和“当前心绪”是独立页面。前两者没有被新功能替代；后端暂时不可用时会显示说明。情绪加载失败可点“重试读取情绪”。

### 11.1 性格与情绪有什么不同

0.10.1 启用自我参考后使用第22章的协同机制：六维为缓慢倾向，文字参考解释经历，旧关键词涨点停用。下面涉及旧角色卡、旧性格整理的操作仅适用于未启用自我参考的兼容模式。

性格是相对长期的表达底色、边界和偏好；情绪是近期事件引起的变化。一次普通请求不应让长期人格立即改变。性格页可以查看和编辑维度，按已有入口从角色卡起草、查看建议或按聊天微调。

从角色卡起草和相关合并可能调用模型。启用人格漂移时，应看清“直接应用”与“只建议”的区别：前者可能自动改变底色，后者需要你采纳。需要稳定人设时先关闭自动漂移或使用建议模式。

### 11.2 当前情绪怎样计算

系统先判断事件类型和对象，再更新短期情绪、较慢的心情及长期底色。状态随时间恢复，标签使用不同的进入和退出阈值，减少边缘状态来回跳动。标签是系统对状态的描述，不是对人的情绪诊断。

普通请求、用户诉苦、任务纠错和真实关系冲突分开处理。久未联系的轻微想念/失落也有单独上限，不应一直累加成强烈生气。

### 11.3 模型理解日常感受与复杂情境

在情绪页开启“模型理解日常感受与复杂情境（老大私聊，每日无上限）”。默认关闭，升级保留已有设置。普通主人私聊也可以进入理解；命令、非主人消息等不在这一付费范围，独立复核仍限制当前文本不超过 1000 字符。

开启连续事件理解且成功返回时，复用它的情绪判断，不另发情绪请求。未取得共享结果时，情绪模型可补一次独立调用。因此共享理解失败的轮次可能同时出现“事件理解”和“情绪复核”费用。没有每日硬上限，查看花费页了解实际用量。

模型解释事件和感受，程序负责证据核验、限幅、去重与淡化。失败时保守处理，不当作用户恶意；打开开关仍不能保证反讽、引用和复杂语境总是判断正确。

### 11.4 情绪异常时怎样排查

1. 找到情绪页显示的最近起因、事件类型、对象和判断来源。
2. 对照具体原话，区分“用户说自己难过”和“用户攻击角色”。
3. 如果是误会，及时明确说“刚才那句话是引用，不是在说你”，必要时引用原消息。
4. 查看是否发生了修正；不要默认所有历史都能无限回放。
5. 记录仍不正常的原句、前后几句、时间和模型状态，便于复现。

情绪页的“联想带来的主观感受”单独展示临时印象与偏移，具体规则见第 13 章。

当前澄清只尝试修正同聊天、同说话人最近匹配事件，受约十分钟及最多十六个事件的窗口限制。窗口外或状态被手动修改后，不能保证自动重算。已经发送的 QQ 消息不会因此被撤回。

### 11.5 日常聊天为什么也能有变化

情绪现在分开处理“发生了什么”“对关系意味着什么”和“此刻产生什么细微感受”。普通聊天可出现温暖、轻快、好奇、安心、牵挂、轻微失落，最多两种并存。例如“拿到面试邀请，很开心但怕赶不上”可以既轻快又牵挂。

有明确语境的日常交流不必全判为“不确定”；模型仍需逐字引用当前消息作为依据。没有依据就允许没有变化，不要求每句话都产生情绪。第三方说了难听的话，不等于用户在攻击角色；纠正答案也不等于关系变差。

细微感受按类型以十二至三十分钟半衰期恢复，限制幅度，不随网页刷新叠加。它不会单独训练关系、长期气候或人格。真实冲突未解决时，轻快/温暖等不能直接盖掉冲突。关系修复仍需明确事件，缓慢变量继续走已有积累规则。

页面在“平静”等主要标签旁显示细微感受，聊天提示词要求它自然影响语气、关注点和提问意愿；不机械报情绪，也不要求你安抚。主标签仍是平静时，也可能已有轻微好奇，不需要为了看见变化而让数值大起大落。

这不是新增六次模型调用。开启连续事件理解时，感受复用同一份输出；关闭时仍可由按需情绪语义复核提供，纯规则回退不编造感受。实际 token 随模型、历史长度、输出和推理而变化，应查看“事件理解/情绪复核”分项。

### 11.6 性格、情绪与心绪怎样联动

稳定性格底色会作为理解当前事件的风格背景。例如好奇心强的设定可能更注意日常分享中的新事物，但不能据此猜测用户在攻击她。温暖、轻快、好奇、安心、牵挂、失落分别在 30、15、12、20、25、20 分钟减半；相同原话不重复增强或续期。用户明确解决触发事件时，相关感受可收束至原来的 15%。

短时感受影响本轮关注与语气，仍受参考预算限制；它们不直接训练长期人格。长期关系和情绪积累继续使用原有开关、样本门槛与冷却。光晕颜色来自现有状态，不是额外情绪评分；0.00 表示接近平常状态，不等于没有感受。点击心境或感受查看依据，也可暂停动效、切换文字。

## 12. 主动联系与催睡

主动联系按空闲时间、允许时间窗、概率、日次数和冷却共同判断。到达时长只是满足一个条件，不代表立即发消息。催睡同样需要功能开启、时间条件和联系人状态等条件满足。

在情绪页相关设置中调整这些项目。先确认目标、时间和总开关，再逐步调整概率或次数；不要同时大幅修改很多参数，否则很难知道是哪项造成频繁联系。

久未联系允许有限的想念、失落或轻微小脾气。用户提前说明要忙时，系统会对部分明确忙碌表达暂停联系；这是有限模式识别，不是完整日程管理。回来正常说话会缓和久未联系的影响，真实冲突仍独立处理。

如果不希望被主动打扰，可以关闭主动联系或催睡。关闭这些功能不等于关闭正常回复或长期记忆整理。空闲联想自身不会主动发消息，也不会替代主动联系开关。

## 13. 空闲联想试验

### 13.1 联想为什么会等待

在“当前心绪”找到“空闲联想与主观感受”，勾选“启用空闲联想（试验）”。它仍默认关闭，只面向主人私聊：

1. 收到符合条件的新消息后，安静约两分钟才尝试生成。
2. 从同一聊天的真实记忆出发，通常两步；有明确新角度或澄清问题用途时最多三步、三次模型调用；两轮至少间隔三十分钟。
3. 话题保留十分钟。下一句不相关时暂存，不会重置有效期，也不会为了等话题反复调用模型。
4. 后续聊天召回了所需来源时，再单独读取原始事实，确认没有删除、替换或过期，然后准备回复参考。
5. 同一话题只准备一次。聊天模型可以采用，也可以忽略；角色不必机械地把所有想到的内容说出来。

例如：角色想到“雨天可以聊读书”。你先说“帮我看代码”，它会继续存着；几分钟后你聊到雨天阅读，仍有机会接上。十分钟后才回来则已经过期。

目前相关性仍采用保守的来源匹配：需要当前普通记忆召回覆盖话题引用的来源。它提高了等待利用率，但没有承诺所有语义相关话题都能触发。

### 13.2 去向记录怎么看

点击“查看联想去向”，可以看到话题、来源、到期时间，以及最近状态。

| 状态 | 含义 |
| --- | --- |
| 已生成，等待合适话题 | 有临时话题，还没用于当前回复 |
| 本轮不相关，继续暂存 | 当前召回没有覆盖引用来源，原有效期不变 |
| 来源校验暂不可用 | 服务暂不可用，暂不注入；有效期内允许后续再试 |
| 已准备回复参考 | 已组装参考，尚未确认投递给模型 |
| 已交给聊天模型 | 提示词请求被接受；不表示模型实际说出来了，也不表示 QQ 已发送成功 |
| 投递未接受或未启动模型 | 请求失败或转成直接命令，参考已丢弃 |
| 投递结果未知 | 无法确认接受结果，不重复注入以免重复使用 |
| 来源已变化或失效 | 引用事实已修改、删除、替换或过期，丢弃对应想法 |
| 话题已过期 | 超过十分钟，不再使用 |
| 被新消息打断 | 新消息到来，尚未完成的旧一轮生成失效 |

记录位于桥接 `state/idle-association-audit.json`，最多保存最近 40 条、读取时保留七天内记录；页面显示最近 20 条。它是本地诊断记录，不进入向量记忆库。重启保留诊断记录，但不会复活临时话题和感受。

### 13.3 “想多了”如何影响情绪

当前心绪提供独立开关：**允许联想产生轻微主观感受（试验）**，默认关闭。要产生这种感受，需要同时开启空闲联想和情绪功能。

开启后，同一次联想调用可以附带一个主观印象，例如“也许最近压力大，我有一点担心”。它与“用户明确说自己压力大”是两种记录：

| 内容 | 保存和使用方式 |
| --- | --- |
| 用户原话支持的事实 | 继续走既有事实提取、确认和冲突处理 |
| 角色的模糊理解 | 标记为未确认，只作为临时主观印象 |
| 主观印象带来的感受 | 只影响主人私聊的轻微措辞和情绪页面的暂时偏移 |

规则如下：

- 感受类型限定为好奇、温暖、担心，不根据猜测增加冲突分或关系恶化。
- 模型给出的把握度最多记为 0.6，它只是生成记录值，不是真实准确率。
- 愉悦度偏移最多 ±0.04，唤醒度最多 +0.03；五分钟减半，十分钟失效。
- 展示时计算偏移，重复刷新不会累加；不会写入真实事件情绪、长期气候、人格或情景事实。
- 新的主人私聊消息到来，就先清除旧感受，再处理当前消息。用户解释、纠正后，不保留旧猜测继续影响语气。临时话题仍可以在有效期内等待相关场景。
- 若后续话题相关，模型可以获得一次“刚才曾想到……”的历史主观印象参考，因此有机会自然说出关心或联想。它明确标为过去的未确认印象，不会重新激活情绪偏移；当前消息、澄清和拒绝优先，不能拿旧印象反驳用户。关闭主观感受开关后，这种参考也停止提供。
- 关闭开关、关闭空闲联想或手动重置情绪，都能清除这层临时感受。
- 提示词要求不能把沉默当成“不在乎”、不能用上一步的猜测支持下一步的猜测；这属于模型语义约束，不是对模型理解永远正确的保证。数值上限、过期和不进入事实库则由代码控制。

它不额外创建主动联系任务。已有主动联系功能满足自己的窗口和频率条件时，可以读取当时仍有效的轻微主观感受；关闭主动联系不会因为联想而被绕过。

这仍是有限的短程联想，没有实现持久的自主思维或长期主观信念系统。是否自然、是否容易误解，仍需实际对话观察。

## 14. 当前心绪：挂念与待验证认识

### 14.1 如何开启

安装同版本插件与桥接后，打开网页的“当前心绪”标签，勾选“启用连续事件理解（试验）”。默认关闭，配置为 `socialV2.continuity.enabled`。只处理当前运行模式允许的主人私聊，不跨聊天共享，也不读取其他人的连续状态。

开启后，符合条件的新文本消息先交给无工具模型整理一次事件。挂念、主观认识、关系观察使用同一结果；情绪功能开启时也复用其中的情绪分类，避免成功后再单独调用一次情绪复核。普通聊天可以完全没有状态更新，不按固定主题词表决定是否理解。

命令、敏感内容、空消息不送入这项分析；超过 2,000 字的消息不截断后猜测，使用原有聊天处理。当前流程不分析图片中的隐含事件。系统仍沿用原来的消息记录、事实提取与冲突处理，连续状态不回写事实库。

### 14.2 一轮消息怎样产生变化

主人发来新消息 → 模型整理事件与原话依据 → 更新挂念、暂时认识和关系观察 → 已有情绪系统采用事件分类 → 选择这轮相关的参考 → 聊天模型回答当前请求 → 记录请求与发送结果。

普通聊天可以没有任何状态变化。比如先说“明天面试有点紧张”，再问一个代码问题：挂念可以继续保留，但不应该强行插进代码回答。后来你澄清“不是担心表现，是怕赶不上车”，认识应修正；你说“面试结束了”，挂念可以结束。

### 14.3 当前挂念

挂念是有原话依据、尚未结束的事情。例如“明天面试，有点紧张”，可以形成“明天的面试”。它保存标题、待解决部分、来源消息、状态和期限。

- 切到代码等无关话题：保留挂念，不把它放入这轮回复参考。
- 用户主动重提：可以重新成为本轮重点。
- “暂时不想聊”：暂停。暂停后不注入，也不给空闲联想提供线索；仅用户主动重提时才应恢复。
- “已经结束了”：关闭。关闭项目不会自动重新打开。
- 到期：失效，不把长时间沉默解释成事情仍在持续。

期限由事件理解提出，代码限制在 1～168 小时；不确定时提示模型采用 72 小时。它不是精确日程提醒系统，也不承诺在指定时刻主动联系。当前挂念最多 20 条，容量满时优先移出终态项目，否则移出最早项目并记录原因。原聊天与事实记忆不因此删除。

控制台提供“暂不聊这件事”“结束这件事”，点击后立即使尚未完成的旧理解失效。历史项目仍可查来源。

### 14.4 待验证认识

这里不需要用户逐条点击“确认是真的”。后续真实聊天可提供支持或纠正；没有新证据就逐渐淡化。长期记忆里的“待确认事实”才是另一套事实核对流程。

认识表示“她暂时怎样理解”，例如“也许比较担心面试表现”。它不是“用户确实担心面试表现”的事实。

用户说“不是怕面试，是怕赶不上车”时，旧认识应修正或否定。修正前的内容保留在记录中，新认识重新从本次证据开始，不能继承旧认识的支持次数。点击“这个理解不对”也可以手动否定。

程序按消息 ID、原文指纹与去除标点空白后的证据片段去重：同一消息的重放、相同原文换消息 ID、同一内容在摘要或日记里重述，都不能增加该认识的证据数。只接受当前用户消息中的逐字片段；引用旧联想或其他认识不能作为新证据。

同一认识至少有三个不同日桶的原话证据，且首末跨度不少于 72 小时，才标记“多次经历支持，仍可修正”。日桶按 UTC 划分。初始生成置信度记为 0.35，满足观察条件后最高为 0.6；这是内部规则值，不是准确率。支持次数多不意味着认识就是真的，模型也可能误判哪些经历支持同一认识。

参考强度以最近一次有效新证据为起点，每七天减半；低于 0.12 时不再放入回复参考，三十天无新证据则过期。刷新页面只计算衰减，不会重复扣减。只有新的有效证据能刷新保留期限和恢复参考强度；同一句话套上不同前后文、重述同一次经历或无法确认是否为新经历，都不续期。重复原文和片段由代码拦截；不同措辞是否在重述同一经历，由模型对照已有原话判断，仍可能误判。旧版状态迁移按实际证据时间纠正期限，不沿用重复提及时错误延长的期限。

活动认识最多从有效新证据保留 30 天；最多 20 条，每条保留最近 12 个去重证据、最近三次修正及最多 256 个去重指纹。已否定内容作为历史记录保留到容量清理，并在后续理解中提醒不能复活。代码能阻止完全相同文本重复创建，换一种说法是否仍是同一认识仍依赖模型语义判断。

这些认识不会自动进入长期事实、日记、人格整理或长期情绪训练。原有的人格微调建议仍使用原来的样本、跨度、冷却和幅度约束；本版没有把“推测用户的规律”直接变成“角色的人格”。

### 14.5 关系观察与情绪

三项关系慢变量分别为信任倾向、熟悉积累、未解决张力，初始基线是 50、0、0。它们是设计参数，不是对人类感情的测量。

只有事件分类明确指向角色、置信度至少 0.85，且模型给出相匹配的明确关系证据时，才允许变化：信任或不信任单次最多变动 1 分，熟悉积累同日最多 1 分，冲突或修复使张力单次最多变动 3 分。每天最多接受两次关系变化，这是幅度限制，不是模型调用次数限制。道歉降低张力，不直接恢复全部信任。

忙碌、离开、任务纠错、用户自身难过、第三方台词和生成的联想不会直接改变关系。代码检查事件类型与关系类型配对和原话来源，但原话究竟属于哪种语义仍可能被模型误判。

关系参数只在当前消息确实谈及关系时提供为可选背景，不直接叠加到情绪分数，也不直接改写人格。每条事件会记录已有情绪系统实际采用后的变化，避免页面把“请求的变化”冒充“实际发生的变化”。

### 14.6 空闲联想如何衔接

开启本功能时，进行中的挂念可以补充空闲联想的检索线索。它不是联想的新证据：联想仍须从同一聊天的原始记忆开始，引用原始记忆 ID，使用前再次检查来源。仅有挂念、但记忆检索没有合格来源时，不会硬造联想。

通常两步、有明确用途时最多三步；冷却、十分钟暂存、来源失效检查和独立主观感受开关保持有效。这里没有无限自主思考，没有增加主动发送入口。

### 14.7 页面与故障处理

“当前心绪”显示挂念、认识、原话依据、修正历史、关系观察以及事件处理和回复去向，每 15 秒刷新一次，也可手动刷新。

- 模型接受：只说明本轮请求已接受，不能证明某条参考被表达。
- 实际发送成功：说明关联回复已发出，仍不能证明使用了某条挂念。
- 投递结果未知：不能当作成功，也不补造成功记录。
- 状态保存异常：页面会提示，磁盘故障可能导致重启丢失最近状态。
- 理解失败、格式不合格或超时：本轮回退已有处理，不使用旧一轮的相关性选择。

挂念、认识和最近 60 条事件记录保存在桥接 `state/continuity.json`，包含部分原话，属于本地私有状态，不能放进公开发布附件。重启保留未到期的工作状态，但清除上一轮的“本轮相关”选择。关闭开关保留历史，不继续生成或使用参考；重新开启后等待新的合格消息。

新消息、关闭开关及手动修正会使过时的分析结果失效。正常单次分析等待上限约 8 秒，后台设置会话也计入这段等待；最多同时保留两次尚未返回的事件理解（包括本地已超时、后台尚未结束的请求），忙碌时回退原有处理。网络超时不等于服务商没有消耗 token。

### 14.8 费用

“事件理解”单独记入花费页。每条合格消息最多新增一次事件理解调用，不设置每日硬上限；成功时复用情绪分类，不再重复发起本轮独立情绪复核。事件理解失败后，原有情绪复核仍可能按自身条件调用，因此异常轮次可能同时出现两个分项。

输入包含本轮消息、最多四条近期原话片段以及有界的挂念、认识和对应原话证据（每条最多十二个），供模型区分新经历与旧事重述。不把这些历史原话当成本轮新证据。用量随文本和当前状态数量变化，不能承诺固定 token 数；账本以模型返回 usage 为准。没有有效 usage 的请求不虚构费用。

### 14.9 可视化和文字列表怎样选择

页面右上角切换“可视化”或“文字列表”，浏览器记住选择。可视化包括四个来源阶段、挂念与认识地图、详情、关系观察和最近变化；文字列表保留完整事件与投递结果。两种视图读取同一状态，不产生额外模型调用。

地图每页最多六条记录，可筛选当前/历史/全部。点一张卡片查看原话、修正历史和期限。虚线只表示本轮确实选入参考，不代表推测出来的因果关系。认识的“参考强度”是内部权重，不是准确率。

“空闲联想与主观感受”已与心绪整合：真实记忆 → 临时话题 → 未确认印象 → 此刻回应基调。没有状态就显示空状态，不为了填满图表生成内容。点“查看联想去向”查看完整记录。“情绪”页继续保留曲线和参数，并提供返回心绪页的入口。

连续事件理解、空闲联想、主观感受仍能分别开关；关闭事件理解不自动关闭联想，关闭联想就不会产生新的联想感受。感受展示不重复加分，不把猜测变成事实。

总览中的“补充关联记忆”（原“补充关联记忆”）继续保留：它在检索时补找相关旧记忆，默认最多一条，配置最多两条，不调用模型生成念头；可能增加回复输入 token。这与空闲时最多三步生成话题不同。

## 15. 玩梗功能

“玩梗”页用于查看可选梗库与策略。梗库是另行准备的本地 SQLite 数据，不随本插件发布；未安装梗库时，不代表长期记忆库损坏。

可按页面提供的总开关、私聊/群聊和主动候选设置控制。每轮只给少量候选，是否使用仍由模型决定；开启不等于每次都讲梗。系统对部分政治、敏感和攻击类内容有限制，但规则不能保证识别全部不合适表达。

如更换梗库，应先备份并保持兼容表结构。来源和许可见仓库 `docs/memes.md`。不要把网页显示的梗库数量当成安装包一定自带的数据数量。

## 16. 模型用量与费用

### 16.1 哪些功能需要模型

| 操作 | 模型调用情况 |
| --- | --- |
| 浏览、文字筛选、手动编辑 | 通常不需要聊天模型生成 |
| 本地语义检索 | 使用本地向量模型，不是一次聊天生成调用 |
| 自动/手动提取 | 一次提取；声明完成的消息通常再独立检查一次 |
| 遗漏续处理、失败后重试 | 可能增加请求和费用 |
| 确认/恢复事实 | 有旧事实需核对时，每批最多八条，可能调用一次 |
| 日常感受与情绪复核 | 开启且没有可复用共享结果时，合格主人私聊可新增一次 |
| 摘要、日记补页、性格起草 | 相应生成操作可能调用模型 |
| 连续事件理解 | 开启后，每条合格主人文本最多一次；成功时复用情绪分类，无每日硬上限 |
| 空闲联想 | 开启且满足条件时，通常两次，有明确用途时最多三次 |

### 16.2 如何看“花费”页

“累计 · 功能花费”显示账本累计数据；“时间统计”和“所选时段 · 功能花费”跟随 24 小时、7 天、30 天按钮。

后台调用现在按入口区分：记忆提取、提取查漏、事实复核、候选核对、空闲联想、情绪复核、事件理解、聊天摘要、性格整理、性格草案、日记生成、图片理解，以及其他内部调用。它们仍属于“可塑性记忆”，不会再被当成角色对话。

- 分项归属与用量记录一起保存，正常完成、重连和重启不会抹掉标签。
- 升级前统一归类的记录保留为“历史未分项”，不会根据内容猜测用途。
- 功能汇总在聊天分页之前计算；较小的功能花费不会因为聊天数量多而消失。
- 趋势直接按账本内仍保留的逐次用量聚合，不再只拿最近 1,000 轮拼图。前端展示所有返回的时间桶，不再截掉前半段。
- 图中边界覆盖从查询时刻往前的完整所选时长；没有用量的时段仍显示空桶。
- 推理 token 是输出 token 的细分，按照现有账本口径，不在输出之后再重复相加。

**累计值与趋势图之和不一定相等。** 较早的记录可能只有累计快照，或逐次明细已压缩淘汰。它们仍保留在累计金额中，但无法可靠地分配到某个时间点。页面会提示明细限制，不把历史累计值伪装成今天的消费。计费用量记录数包含重试，也不等同于成功完成的整理批次。

费用按当前配置的模型价目表估算；模型没有返回 usage、超时后未收到用量等情况不能靠本地账本推算出真实账单，最终以服务商账单为准。

事件理解正常等待上限约 8 秒，同时最多保留两个未返回的请求。超时或忙碌时回退原有聊天；超时不表示服务商一定没有产生 token。费用以 usage 记录和服务商账单为准。

### 16.3 怎样控制消耗

优先限制不需要的聊天范围、关闭不需要的试验功能，再设置自动整理批次额度。频繁手动整理或重试会额外消耗。确认大量历史前可以观察进度并停止后续批次，但已经发出的请求可能仍计费。

不要把“每天不限”理解为每轮都应调用。情绪复核、整理额度和主动联系次数分别控制不同流程。

### 16.4 历史未分项与旧黑话费用

“历史未分项”表示旧账本当时没有记录具体用途；“历史内部／黑话学习”也不代表里面全是黑话任务。旧标签里可能混有记忆提取、图片理解、日记或性格整理，不能整类删除。

花费页的“历史费用核对”显示已经核实的分类、排除项以及仍待核实的部分。只有原始会话和专用调用模板能证明属于旧黑话任务时才排除；未知或混合用途保留。核对数据是上方总额的历史子集，不要再加一次。

离线工具 `node scripts/audit-usage-history.mjs --home DSH_HOME --output REVIEW.json` 只生成核对文件，不调用模型、不改原账本。由维护者核对后安装到 `token-usage.jsonl.attribution.json`，重启桥接生效。移走该侧文件并重启能恢复原统计。升级包不包含你个人的核对记录。

## 17. 备份、升级和回退

### 17.1 备份哪些内容

| 内容 | 常见位置 |
| --- | --- |
| 长期记忆、原文、摘要、复核页进度 | `~/.dsh/memvec/memories.db` 及相关 WAL/SHM |
| 待处理队列和桥接状态 | `~/.dsh/qq-bridge/state/` |
| 桥接配置与主动联系设置 | 桥接 `config.json`、`owner-contact.json` |
| 性格、情绪、审计与私密日记等 | `~/.dsh/feiyu-memory-console/` |
| 公开日记 | `~/.dsh/whale-diary.md` |
| 程序与回退材料 | 旧插件源码、独立 `server.py`、桥接 `src/` 和 `.runtime-backups/` |

以实际路径为准。先停止写入相关服务再复制完整数据，或使用 SQLite 在线备份。运行时只复制一个 `.db` 可能遗漏尚在 WAL 中的数据。

### 17.2 升级顺序

下载同一版本的包和升级指南 → 备份 → 退出 DSH、桥接及记忆服务 → 更新插件 → 检查并更新桥接运行时 → 更新独立 memvec 源码 → 重启 → 核对版本、服务、队列和已有事实。

退出 DSH 窗口不一定停止独立 node/Python 服务。需要确认端口和对应进程；不要按程序名结束全部 node 或 Python 进程，它们可能属于其他应用。

### 17.3 回退的范围

停止桥接后，用本次安装所用版本的安装器执行 `--undo`，只恢复它管理的运行时文件和回执。插件源码和 memvec 源码需另外恢复。

回退数据库会丢失备份之后新增的内容，不能把旧数据库直接覆盖当前库当成常规降级。先保留当前完整副本，再明确需要恢复的范围。程序回退与数据回滚是两件事。

## 18. 常见问题与排查

| 现象 | 优先检查与处理 |
| --- | --- |
| 更新后仍显示旧版 | 重启 DSH、刷新网页，检查实际加载的插件目录 |
| 突然变成零条记忆 | 查数据库路径是否变了，不要先删除或重新导入 |
| 记忆服务离线 | 检查 Python 环境、依赖、模型下载和端口 9881 |
| QQ 能聊但长期记忆不更新 | 检查 memvec、整理总开关、会话范围、队列和模型调用 |
| 群聊没有入队 | 默认需要 @/回复；检查群聊参与策略及授权范围 |
| 队列停着不动 | 看重试原因、额度、低产出暂停、超长消息和服务繁忙 |
| 已检查但没有新增 | 可能是闲聊、重复、转述或被排除；重要内容对照原话 |
| 显示提取时待确认，列表找不到 | 选对聊天和状态；记录可能后来已确认、删除或过期 |
| 八条之后继续复核很慢 | 每批都可能请求模型；查看进度，必要时停止后续检查 |
| 一直提示历史变化 | 检查同期是否编辑或新增了相关事实，稍后重试 |
| 喜欢 A 与不喜欢 B 被说成冲突 | 比较对象、条件和原话，确实都成立时选择分别保留 |
| 情绪或性格没有数据 | 入口仍保留；检查桥接状态与版本，情绪页可重试读取 |
| 确认时许多记忆都是真的 | 选“确认这条，并保留全部已有记忆”，不要因不确定而覆盖 |
| 待验证认识一直没人确认 | 无需逐条审批；没有新证据会淡化、过期，错误理解可手动否定 |
| 记忆正确但回复没用到 | 检查检索范围、预算与实际回合，不只看控制台预览 |
| 情绪突然变差 | 核对事件类型、对象、原话及复核来源，及时澄清 |
| 空闲联想没有内容 | 检查开关、主人私聊、新消息、空闲时间、冷却和模型 |
| 摘要或日记写错了 | 在对应层处理，不能假定删除摘要也会删掉长期记忆 |
| 无法撤销 | 后续数据可能变化，或该操作不支持撤销；先查看审计 |
| 安装器拒绝覆盖 | 存在未知版本、自定义修改或回执问题，先备份与比对 |
| 刷新后按钮还不可用 | 桥接能力未更新或后端未重启，只换网页不够 |

反馈问题时附版本、涉及页面、操作步骤、期望和实际结果。若涉及语义错误，提供去除私人信息后的原句和必要上下文；不要上传整个真实数据库、密钥或控制令牌。

## 20. 心绪中枢：本轮关注、回应倾向与情境练习

### 20.1 实际流程

主人私聊 → 当前消息登记 → 可选连续事件理解（复用情绪判断、反馈判断） → 原有记忆检索和来源校验 → 汇总挂念、认识、关系、情绪、回应倾向、联想 → 去重与预算筛选 → 参考块与当前请求交给聊天模型 → 沿用原有投递与发送记录。

用户当前请求不参与竞争、不因心情被丢弃。当前心绪面板展示筛选结果；已经提供参考、请求被模型接受、QQ 发送成功是不同阶段，均不能单独证明模型实际采用某个想法。

### 20.2 开关与查看

打开“当前心绪”，首先看到“心绪中枢”。“启用本轮关注筛选”默认开启，仅主人私聊；关闭后沿用原有参考组合。“从明确反馈学习回应倾向”默认关闭，需要连续事件理解同时开启。原有情绪、性格、日记与联想开关保留。

可视化用柔和光晕呈现现有情绪状态，周围最多显示五条可点选参考；点击后查看内容和来源。动效可暂停，也遵循系统的减少动态效果设置。情绪波动表示与平常状态的偏离，0.00 不是没有感受；颜色不是额外计算的情绪分数。文字列表展示相同参考，不会额外生成内容。设置、字符用量和回应习惯收在折叠区。展开“未入选参考与原因”可查看重复、关联不足、同类已足够、条数已满或字符预算不足等原因。来源与原始参考包含主体、时间标记和证据编号，方便排查。

默认最多五条、2400 UTF-16 字符，包含标题和完整 JSON 标签。最多两条记忆、两条挂念，其余每类最多一条；先按类型优先值和现有检索分数排序，过长条目整体跳过。这里的分数是调度规则，不是情感测量值或模型准确率。没有实现让模型无限自由分配注意力。

本轮关注只在内存中保存；新的主人消息清空旧展示，异步返回的旧轮次不能覆盖新轮次。五分钟后不再展示上一轮，重启也不复活。记忆、挂念和反馈自身的持久状态不因此删除。

### 20.3 回应倾向学什么

当前支持六种有限策略：困扰时先倾听、先简短再按需展开、建议前先确认需要、纠错时说明改动依据、接住日常分享的细节、自然收尾留空间。它们是表达建议，不是新的人格、权限或任务拒绝规则。用户已明确要求详细方案时，简短倾向不能省略细节。

模型在同一次事件理解中判断是否有明确评价回应方式的原话，程序再验证来源、逐字引用、置信度不低于 0.9、策略名及经历标记。没有明确反馈用空数组。普通聊天、说自己累、泛泛的谢谢、第三方故事、引用、假设、自己的回复、联想和练习都不应成为反馈依据。代码能检查来源和原话，却不能保证模型识别反讽或引用总是正确。

至少三个不同日期的独立支持，支持比例不低于 75%，衰减后的参考强度不低于 0.45，最近一条仍为支持且未超过三十天，才可能按当前事件使用。每个 UTC 日期最多一票，以当天最后一条有效反馈为准；不是每说一句就增加一票。同一来源编号、规范化相同原话、模型标为重复或不确定的经历不累加，也不续期。换说法的同一事件仍可能被模型误判为独立经历，需要观察和修正。

支持权重三十天减半，最近六十天反馈参与计算，无新反馈满三十天不再使用。明确反对立即暂停；后续支持仍需重新满足全部条件，不自动恢复满分。

### 20.4 如何修正

在倾向卡片展开“查看反馈依据”，核对原话和来源编号；误记时点“撤销这条反馈”。撤销会立刻重新计算，但保留去重记录，避免同一句以后又被当成新证据。“停用此倾向”禁止使用，恢复后仍须满足证据条件。

全部反馈（含撤销记录）保守上限 96 条；达到后暂停新增并明确提示。不会悄悄删掉旧证据再重复计分。状态保存在桥接 `state/response-patterns.json`，需纳入备份。关闭学习保留记录，停止新学习和倾向注入；关闭连续事件理解也暂停二者。更改设置或修正依据会使正在处理的旧理解失效。

### 20.5 联想怎样参与

短程联想通常最多两步；模型明确指出下一步用途（新角度或澄清问题）时，最多增加到三步，仍受去重、来源校验、新消息中断和停止条件限制。保留同聊天真实来源、十分钟到期和原有轻微感受限制。通过来源校验后，还要参加本轮筛选；没有入选则暂存，不能假装已经用过。准备提供前再次检查是否还是同一个有效想法。关联线索、过去的主观印象和待验证认识始终不作为事实。

### 20.6 Token、练习与边界

本轮筛选不单独调用模型。学习复用事件理解调用，但会增加学习提示、最多 96 条历史反馈及少量输出，费用归“事件理解”；接近容量时，输入可能明显变长。2400 字符只限制聊天参考块，不是 token 上限，也不是整个提示词长度。实际费用看花费页和模型服务商账单。

`npm run simulate:mind` 使用隔离的预设判断演练普通聊天、明确肯定、重复经历、跨日积累、反对、话题切换和旧轮次失效。运行不调用模型、不读取真实状态、不向 QQ 发消息，结果不会写入角色记忆。这是机制回归，不是模型语义准确率测试，更不是自动上课提升人格。

长期对话中的语义误判、联想质量与习惯自然度仍需要实际观察。参考入选不保证表达；有限策略也不等于完整的人类学习系统。

### 20.7 来源与贡献

心绪中枢参考小凌原创「心光」模块及相关设计，经本项目融合、删减与独立实现。本插件亦有 QQ 用户夜怀瑾、小甘心的贡献。保留的是有限关注、经历反馈与情境练习思路，没有直接打包原模块源码、依赖或状态文件。详细署名见 [致谢](../ACKNOWLEDGEMENTS.md)。

## 21. 心迹桥接管理：两个页面各看什么

3080 的“心迹 · 可塑性记忆”是记忆、心绪、人格和花费工作台；3100 是桥接管理，查看连接状态、白名单、仿真、底层指令和运维。桥接页面会显示实际引擎与版本。名字改成心迹不代表重新实现了 QQ 协议：现有 QQ 收发和二代调度仍由兼容层承载。

在3100的“访问与安全”维护私聊和群白名单；“二代仿真”调整工具及唤醒；“人格与指令”查看交流预设并跳转3080性格页。旧黑话书签回到总览，不再启动黑话提取。可塑性记忆的“玩梗”仍在，保留本地梗库和按需查询。

访问令牌是本机管理凭据，不能发给别人。缺少令牌时从原本机启动入口进入或检查桥接 state/console-token，不要为了方便关闭鉴权。源文件和用户状态都在本机，发布包不包含你的令牌。

## 22. 六维、自我参考和防 AI 味

### 22.1 为什么分三部分

六维表达缓慢变化的倾向；自我参考用文字解释真实相处带来的身份理解、共同经历、性格倾向和兴趣探索；自然表达规则决定如何说话。心绪则描述此刻的感受。它们协作，不互相替代。缺乏依据时可以没有来历或兴趣条目，不编造故事填满面板。

### 22.2 启用与迁入

按升级指南在既有 socialV2 配置合并 selfReference.enabled=true，并开启连续事件理解。首次启用保留自己的六维数值；旧角色卡不再作为固定身份脚本，旧文件仍保留。新的文字参考从后续私聊形成，不自动导入旧聊天，也不会带入作者的性格和经历。没有开启时继续兼容旧性格机制。

### 22.3 怎样成长、怎样控制

事件理解成功后，当前主人原话进入成长队列；命令、重复原话和不允许的聊天不作为成长证据。自动整理至少12条、两次尝试间隔至少6小时、每批最多32条，和六维建议共用一次模型调用，计入“性格整理”。失败保留队列。不是每条消息都额外调用一次人格模型。

六维每次只允许小幅变化：同一维需至少3次、跨3个自然日的独立经历支持同方向，置信度至少0.9；每7天最多变化一次，每次最多2维各1点，并受参考起点与边界限制。重复原话、同一件事换说法不应累计；语义去重仍可能被模型误判，所以保留证据与恢复入口。模型不调整权限。

在“性格”查看六条刻度，下方展开“修正当前值、参考起点和变化边界”。填写原因后保存；数值需在0至100，边界0至40，当前值在起点加减边界内。修正清空待积累变化并记录历史。原始值保留，模型不能把短期心情直接当永久性格。

### 22.4 文字参考没有新证据时

30天无新依据逐渐淡化，90天暂不注入，原条目不删除；旧原话或同一经历重述不续期。多日依据支持仍是可修正的认识，不是真理。六维不会因长时间没聊天自动归零。可查看原话、撤回条目或恢复最近20个版本；新快照同时恢复文字和六维，旧快照没有六维则仅恢复文字。恢复保留原话使用记录，避免重复涨点。

### 22.5 防 AI 味在哪里

3100“人格与指令”的聊天预设里保留完整自然表达层：不打分、不复述后下判词、不用记账式确认和护卫台词、不装深沉、不机械追问，保留口语、短句、接梗和自己的判断。认真求助时仍认真回答。原有 fishtalk 继续使用，不靠固定口癖或故意答错制造真人感。

规则源文件是 bridge/conversation-style.md。升级时使用文风同步脚本并重启DSH；只放入聊天预设，不在每条自我参考重复附加整份规则。会增加静态输入长度，但不新增后台模型调用。实际输出仍受聊天模型与上下文影响，需要实际相处观察。

## 23. 联合确认、可复用审核与后台档位

### 23.1 一次问清两个问题

自动确认先用一次模型调用同时回答：完整原话是否明确支持这个候选、它与本页已有记忆是什么关系。程序分别核验原话、人物归属、字面含义、当前适用性以及每条历史关系。原话需满足所有条件且置信度至少0.95；关系低把握按不确定处理，不自动覆盖冲突。

每页最多8条旧记忆，更多历史继续分页。后续页已经有原话回执时只审核关系；全部历史完成且版本未变才能自动确认。原话不支持，即使关系都显示共存也不能自动确认；原话支持但关系冲突，也不能自动覆盖。手动确认代表用户自己的决定，不等同于模型自动通过。

### 23.2 什么情况下不用再花一次钱

成功结果保存进数据库，重启后仍在。相同候选、原话、来源、人物、聊天和内容版本复用结果；同一请求并发时也只调用一次。读取次数变化不触发重审。

新增一条旧事实只使包含新关系的页面需要审核，其他内容未变且回执完整的页面可以跳过。原话纠正、候选改写、人物改变或相关旧事实变化时，对应回执失效；新的最终集合版本仍要检查完整性。其他私聊、其他群、同群其他人的结果不混用。无效、缺项或失败结果不会当成通过。

### 23.3 花费怎么查看和调节

“确认联合复核”记录首批联合调用，“事实复核”记录后续关系页，“性格整理”包含文字与六维共同整理。缓存命中不调用模型。提取和独立查漏仍分开，避免提取器自报完成成为唯一依据。

花费页提供后台各模块low/high/max档位。事件理解、普通情绪和空闲联想默认low；记忆提取、查漏和复杂冲突继续high，聊天本身不随后台滑动条改变。实际可用档位取决于模型服务；降低思考强度不保证每次都省token，也可能影响质量。先减少重复调用，再观察质量与花费。使用不同模型时尤其应检查语义误判。

四组合成样例中联合调用从8次变4次、总token约减少36.5%；这只是候选确认样例，不代表整体固定节省比例，更不代表所有模型一致。长期用量需看自己的账本。


## 24. 本轮交流理解与日常心绪

0.10.1 在原有连续事件理解中加入双方近期原话，帮助判断当前是在分享、求助、反馈还是结束交流。“当前心绪 → 最近动态 → 本轮交流理解（可修正）”可以查看依据。它仍可能判断错误，不代表读心，也不自动改写事实或人格。适用范围、用量和实际测试中的局限见[交流理解检查](../docs/conversation-understanding.md)。Markdown 与 PDF 同步更新。


## 25. 记忆保留、遗忘与省心整理

遗忘规则已改成按内容和后续经历调整：重要性0.5时，日常经历、普通信息、偏好/习惯的初始半衰时间分别为3、7、30天。半衰表示程序可用程度降到一半，不是删除期限或真实回忆概率。主人和其他聊天使用同一规则；旧事实、原时间和有效期保留，迁移后14天不归档。刷新、检索和后台合并不加固；有来源的间隔重申才可能加固。核心、待办和短期便签规则独立。详见[使用说明与科学边界](../docs/content-retention.md)。

### 不想逐条整理怎么办

进入「整理 → 省心整理」，选择聊天后点击「本地预览」。每页最多 50 条，先查看原因和原话。所有条目都可勾选，可全选本页或仅选择建议项；「按建议处理」仅执行符合条件的动作。缺审核时这个按钮可能禁用，但你仍可选择「主动归档所选」，核对弹窗后把不再使用的记录收起。这些操作都不调用语言模型。

主动归档保留原文和来源，但不再参与正常记忆检索；它不会将候选确认成事实。保护期仍约束系统建议，不阻止你的主动归档选择。想让她正式记住的记录应继续保留待审核，不能用归档代替确认。

普通、低重要的到期/充分淡化记录可以批量归档；已完成原话与全部相关事实审核的候选可复用审核确认。有歧义、缺审核、保护期内的记录会继续保留。未过期候选不会因为放得久而归档。批内确认可能使另一条候选的审核失效，系统会跳过它并说明原因。

归档保留正文与来源；下方「最近改了什么」可撤销整批操作，后续已被修改的记录不会被强行覆盖。预览有效 15 分钟，服务重启后需要重新预览。这个入口不会偷偷打开自动审核；确实需要语义判断的记录仍走原审核入口，可能收费。详见[省心整理完整说明](../docs/memory-organizer.md)。

### 候选审核与费用

候选确认若显示“自动核对暂缓，可手动继续”，表示已有关系不确定或存在矛盾，后台已停止继续付费审核，已有记忆没有丢失。手动继续会复核剩余内容；没有完成核对不会自动视为通过。修改或新增事实后只补核对变化项，相关说明见[记忆增长与审核费用](../docs/memory-cost-growth.md)。

## 26. 成长课堂：让参考按需生效

独立的“成长课堂”支持＋新建课程、零调用手写参考、单次模型整理和用户核对后按需使用。默认关闭，同样材料复用草案，不循环自评；旧表达教师与文风蒸馏不再自动运行。课程参考不是事实、人格或模型权重训练。费用单列“成长课堂”。操作、成本边界和科研依据见[成长课堂](../docs/growth-classroom.md)。

### 26.1 从创建到使用

进入「成长课堂」，开启可选模块后点击「＋ 新建课程」。填写想改善的能力、适用情景和示例，例如希望日常分享先回应一个具体细节。创建、编辑和手写参考不调用模型。

需要模型帮助时点击「生成学习草案」，每次最多一次调用；材料与模型设置未变化时复用已有草案。先检查参考是否准确、有无虚构经历，再点击核对启用。最多启用三门课，每轮最多选一门相关参考，不将全部课程塞进每句话。

启用课程的实际选用依赖连续事件理解及当前聊天权限；不开启或条件不满足时不会声称已经学习。遇到不合适的回应，可停用参考、修改课程再核对。旧文风蒸馏和表达教师不再自动运行，不反复让模型自我评分。

### 26.2 花费与效果的边界

手写参考不调用模型，但参考随聊天输入时会占用少量上下文。生成草案会产生费用；本轮选课复用事件理解，但会增加少量输入输出。这里保存的是有条件的表达参考，不会训练模型权重，不保证每次都采用。用实际聊天观察效果，不把模型自评视为已经学会。

### 本版没有实现的候选新流程

将「某人说过某句话」自动保留为可检索经历、再与事实确认分流，是后续设计方向，不属于 v0.10.1。当前待确认记录仍需满足原有审核条件才能成为正常检索中的已确认事实。无需为了清空列表归档想记住的内容。


### 可选审核范围

本版保留默认全量审核，也提供显式开启的相关范围模式：审核选入的同方面事实和少量语义近邻，可能漏掉范围外冲突。页面显示的“审核通过”仅指当前选定范围；原话、有效期和版本检查仍保留。详见[配置与限制](../docs/review-scope.md)。此模式不等于所有候选自动生效。
