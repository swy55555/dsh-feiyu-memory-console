## 1. 先了解：这个插件能做什么

### 1.1 四个部分各管什么

可以把整个系统理解为四个协作部分：DSH 负责运行模型与插件；QQ 桥接负责把允许的 QQ 消息交给模型，并把回复发回去；memvec 负责保存和检索记忆；本插件网页让你查看、核对和管理这些内容。

因此，网页打开不代表 QQ 已连通；QQ 能聊天也不代表记忆服务已启动。总览的启动检查就是用来区分这些情况的。

插件不是完整 QQ 机器人安装器。你仍需准备兼容的 DSH、基础桥接及其 SDK、SnowLuma 和可用 QQ 登录状态。现有安装可以升级；没有基础桥接的新用户，应先完成基础环境配置。

### 1.2 三种内容不要混淆

| 内容 | 通俗解释 | 例子 |
| --- | --- | --- |
| 聊天原文 | 当时说过的话 | 我今天加班，明天再聊 |
| 长期记忆 | 从原话中提取的个人事实 | 我不喜欢香菜 |
| 摘要或联想 | 对聊天的压缩整理，或暂时想到的话题 | 最近工作忙；下次可以聊休息安排 |

“模型说它记住了”只是一句回复。要确认实际保存，应到长期记忆页看记录和来源。“想到一个话题”也不等于多了一条真实事实。

### 1.3 v0.8.12-preview.1 的变化

本版新增后台用途分项记账、完整时间范围的费用图、联想暂存和去向记录，并提供独立开关控制的轻微主观感受。记忆完整性与事实复核继续沿用上一版机制。此版本为预发布，试验效果仍需实际聊天观察。

它不会重新扫描你所有过去的聊天，也不会自动开启跨聊天共享。以前已经漏掉的内容，需要你有选择地重新说明或手动录入。

## 2. 安装前准备与首次启动

### 2.1 需要准备什么

需要 Node.js 24+、Python 3.10+、兼容的 DSH，以及已能正常工作的 QQ 桥接。提取、查漏和摘要需要模型服务；本地向量检索需要 memvec 及其依赖。首次启动向量模型可能需要联网下载，之后可以使用本机缓存。

从 GitHub Release 下载版本一致的插件包、升级指南和手册。`.tgz` 用于插件安装，`-source.zip` 用于查看和部署源码；不要把 GitHub 自动生成的 Source code 按钮误认为包含全部单独发布附件的安装包。

### 2.2 找到三个真实路径

先记下“插件目录”“QQ 桥接目录”“memvec 实际运行目录”。它们可能不在一起。Windows 中 `~` 表示当前用户目录，例如 `C:\Users\你的用户名`；不要照抄他人的用户名。

常见数据目录是 `~/.dsh/memvec`、`~/.dsh/qq-bridge` 和 `~/.dsh/feiyu-memory-console`。如果你改过位置，以自己的配置和启动检查为准。

### 2.3 新环境检查

在插件解压目录打开 PowerShell，执行：

```powershell
npm run doctor
python -m pip install -r memvec/requirements.txt
npm run start:memvec
```

第一条只检查环境。第二条安装 Python 依赖，必须使用你准备运行 memvec 的 Python 环境。第三条启动记忆服务；关闭这个前台窗口会停止服务。

已有数据库的用户不要随意换路径。如果页面突然变成零条记忆，先排查是不是打开了新的空库，不要立即重新导入或删除旧库。

### 2.4 安装桥接更新

先备份并停止已有桥接，再在插件目录执行：

```powershell
node bridge/install-all.mjs --target "D:\your-dsh\qq-bridge" --check
node bridge/install-all.mjs --target "D:\your-dsh\qq-bridge" --apply
```

示例路径必须换成自己的实际目录。`--check` 只检查，`--apply` 才安装。若提示未知版本、自定义修改或备份校验失败，先保留现场并核对差异，不要反复强制覆盖。安装器不会帮你安装基础 SDK，也不会自动升级独立 memvec 文件。

按当前 DSH 的本地插件入口安装 `.tgz` 或链接实际源码目录。升级过插件后重启 DSH，因为宿主路由在启动时加载。memvec 如果独立运行在别处，还需更新其实际使用的 `server.py`，具体见升级指南。

### 2.5 启动和检查

启动 memvec、DSH 和 QQ 桥接。在 DSH 打开可塑性记忆；默认网页地址是 `http://127.0.0.1:3080/dsh-feiyu-memory/`。若你改过宿主端口，请使用实际地址。

总览应显示当前版本、数据库和服务检查结果。默认记忆服务端口为 9881，桥接控制端口为 3100。不要把服务端口开放到公网。桥接控制接口可能需要鉴权，直接用浏览器访问某个 API 返回未授权，不等于桥接没有启动。

## 3. 十分钟上手

### 3.1 做一次简单验证

1. 在允许的私聊里说：“我喜欢喝豆浆。我不喜欢香菜。”
2. 打开“整理”，查看是否出现该聊天的待处理消息。自动整理有等待和批次条件，不保证每条消息立即入库。
3. 如需立即验证，点该聊天的“整理这格”。它会调用模型，通常包含提取和查漏两个步骤。
4. 查看“消息处理状态与遗漏检查”，确认是在排队、检查、重试，还是已经完成。
5. 打开“长期记忆”，选中对应聊天，分别查看“活着”和“待确认”。事实置信度及判断结果不同，落入的状态也可能不同。
6. 对照原话核对两条记录，尤其检查“不喜欢”有没有变成“喜欢”。

如果没有新增事实，不要只看机器人回复。沿着“有没有入队 → 是否提取 → 是否发现遗漏 → 是否待确认”的顺序排查。

### 3.2 推荐的日常检查习惯

平时正常聊天即可。偶尔查看待确认内容、失败重试和模型用量；遇到错误，先核对来源，再决定改正文、归档或删除。对于重要的偏好、承诺或待办，用完整、明确的一句话说明，比只说“还是照旧”更容易准确保存。

## 4. 总览与功能开关

总览用于快速确认运行情况，包括启动检查、记忆数量、待处理队列和功能入口。顶部版本来自实际加载的后端，不是只写在网页上的固定文案。

如果更新后仍显示旧版，先重启 DSH并刷新网页，再核对加载的插件目录。仅刷新无法重载所有后端路由。

“跨聊天记忆共享”与“空闲联想”是两件事。共享允许检索其他聊天的部分记忆；联想试验只从主人当前私聊的记忆出发。默认均不应因升级被自动打开，已有设置会保留。

跨聊天共享的过滤不是完整语义隐私审查。涉及真实姓名、住址、凭据或不想传播的内容时，不要依赖过滤器保证不外泄。关闭共享后，正常同聊天召回仍可继续。

## 5. 长期记忆：查看、创建和维护

### 5.1 如何找到一条记录

进入“长期记忆”，先选择聊天，再选择状态、层级和排序。输入文字可做文字筛选；“语义找”用于找意思相近的内容。记录卡片中的原话、来源时间和说话人，是判断是否准确的重要依据。

| 状态 | 含义 | 通常怎么处理 |
| --- | --- | --- |
| 活着（active） | 当前有效的已确认记忆 | 检查来源；必要时编辑、归档或删除 |
| 待确认（candidate） | 尚待核对，可能有冲突或不确定 | 对照原话确认，不能当作已采纳的事实 |
| 已归档（archived） | 暂不参与正常有效记忆使用 | 需要时恢复，恢复也要核对冲突 |
| 被取代（superseded） | 已有另一条事实代替它 | 查看替代关系，不应只因记录较新就覆盖 |
| 已删除（deleted） | 软删除状态 | 若页面支持可恢复；不等于清除所有备份 |
| 已完成（completed） | 已完成的待办 | 保留完成记录，不继续作为未完成任务 |

### 5.2 层级与重要度

“普通”会受到遗忘、到期与整理规则影响；“核心”用于希望长期保留的事实；“待办”用于做完前需要记住的任务。层级和重要度影响保存或检索策略，不保证模型每次回复都提到它。

自动提取的计划和经历通常有到期时间。若这是长期有效的承诺，请核对层级和有效期，不要默认所有“记住”都会永久保存。

### 5.3 手动新增和编辑

点击新增入口，选择“记到哪”，写清事实正文，按需要设置层级、重要度和说话人。正文最多 500 字；建议一条记录只放一个清楚的事实。

“事实键”用于分类，不是同键自动覆盖规则。不要为了让一条新事实替换旧事实而随意复用键；应走核对和明确选择流程。群聊记录尤其要确认说话人，避免把甲的偏好记到乙身上。

编辑前先展开来源。改成的内容应有真实依据，不能把猜测直接改成事实。无法确定时先归档或保留待核对，比写一个看似正确的结论更稳妥。

### 5.4 归档、删除、恢复和导出

暂时不想使用一条记忆，可归档；确定不应保留为当前记忆，可删除。恢复时系统仍要检查现有事实，不能用恢复绕过冲突核对。导出适合阅读和转移记录，不等于完整应用备份。

部分操作会在“整理 → 操作记录”中提供撤销。后来有其他修改时，为防止覆盖新数据，撤销可能被拒绝。没有撤销入口的操作不要假定可以一键恢复。

## 6. 冲突核对：确认与恢复

### 6.1 哪些情况能同时成立

| 两条信息 | 应怎样理解 |
| --- | --- |
| 不喜欢煎饼；喜欢小笼包 | 对象不同，可以共存 |
| 工作日喝咖啡；周末喝茶 | 条件不同，可以共存 |
| 喜欢茶；只喝无糖茶 | 可能是补充，需要保留限制条件 |
| 以前喜欢咖啡；现在不喜欢了 | 明确改口，可能替换旧偏好 |
| 喜欢咖啡；不喜欢咖啡 | 若时间和条件不清，应先核对 |

同属一种分类、文字相似或入库时间较新，都不足以证明应该替换。检查对象、肯否、适用条件、时间和说话人。

### 6.2 点击确认后发生什么

系统取同一聊天、同一主体的有效已确认事实，每批最多八条交给模型核对。超过八条会继续下一批，网页显示“历史已复核 X/Y 条”。进度保存在数据库中，失败后可再次点击继续。

“停止后续检查”停止后面的批次，不保证能取消已经发出的模型请求；已完成批次会保留。只有需要检查的历史完成后，才进入确认或冲突选择。普通检索更新阅读次数不会重置进度；事实正文、状态或来源发生相关变化时，需要重新核对。

### 6.3 弹窗中的选择

先看候选或待恢复记录，再逐条看列出的当前事实及来源。

- **暂不处理**：关闭弹窗，先不作决定。
- **保留现状**：确认候选时，候选移入归档；恢复操作中则保持未恢复。
- **两条都成立，分别保留**：两条均作为有效事实保留，原有事实不会被覆盖。
- **以候选为准**：替换弹窗中列出的相关已确认事实。先检查每条，避免一次替换不该动的记录。

如果提示历史尚未检查完或模型暂不可用，保留现场后重试。不要把“没能判定冲突”理解为“确定没有冲突”。

### 6.4 跨聊天与旧 global 记录

本次核对不会扫描其他聊天的人，也不会把跨聊天共享开关当成修改权限。旧 global 记录主要供查阅；需要继续使用时，应在具体聊天中重新建立有来源的事实，而不是绕过范围保护直接恢复。

## 7. 整理队列与独立遗漏检查

### 7.1 一条消息怎样变成记忆

流程是：允许的消息进入队列 → 提取模型逐事实整理 → 完成声明交给独立调用核查 → 保存有效条目 → 完整处理的消息移出队列。中间失败、遗漏或不确定的消息会保留，以便继续处理。

独立检查使用新的无工具调用，但通常仍是同一模型服务，不是人类审核，也不一定是另一种模型。两个调用仍可能犯相同错误。

### 7.2 哪些聊天会进入队列

允许参与的私聊不再要求出现“喜欢”“记住”等固定词。群聊默认 addressed 策略只处理 @ 或回复机器人的消息；semantic 策略可处理允许群中的普通发言，旧 signals 配置等同 semantic。off 关闭群聊提取。

会话授权、总开关、机器人过滤和命令过滤仍生效。不在授权范围的聊天不会因为一句话很重要就自动入队。暂停自动整理时，新的消息不再进入该整理队列，已有队列保留；这期间的消息不会在重新开启后自动全部补回。

### 7.3 手动整理和额度

在“整理”找到对应聊天，点“整理这格”。每次最多选择 12 条消息，并受文本预算约束；单批输出也有限，多事实消息可能分几次完成。操作只针对选中的聊天，不会因为它空了而改动别的聊天。

手动整理可以越过自动批次额度和重试等待，但仍要满足会话范围、服务可用及任务不忙等条件。没有事实的闲聊产生零条记录也正常。

新配置总额度默认不限，`0` 表示不限；群聊默认每天最多 20 个成功整理批次。旧配置原样保留。成功批次可能包含两次模型调用，失败请求也可能产生费用，因此额度不是严格的 token 或金额上限。

### 7.4 看懂消息处理状态

在“整理”展开“查看消息处理状态与遗漏检查”。

| 状态 | 表示什么 | 建议动作 |
| --- | --- | --- |
| 待处理 | 消息还在队列 | 等待，或手动整理 |
| 正在提取 | 正在请求整理模型 | 等待，避免连续重复点击 |
| 正在检查遗漏 | 正在对照原话查漏 | 等待检查完成 |
| 发现遗漏 / 继续处理 | 有未完整处理的内容 | 查看待补齐原话，再等下一轮 |
| 待复核 | 归属或完整性等仍不确定 | 对照原话，必要时人工整理 |
| 失败重试 | 模型、格式或存储环节失败 | 看原因，修好服务后重试 |
| 已检查，无新增有效事实 | 检查后没有新增可保存事实 | 闲聊可能正常；重要内容可人工核对 |
| 提取时已记住 | 处理当时有有效记忆 | 到长期记忆页看当前状态 |
| 提取时待确认 | 当时生成了候选 | 去长期记忆的待确认列表核对 |
| 队列容量限制 | 达到配置容量，未继续整理 | 重要内容按原话手动补录 |

处理记录最多显示近期 500 条；不是完整聊天档案。后来确认、删除或过期不会把旧处理回执变成实时事实状态。

### 7.5 为什么还有等待

失败按 30 秒到 30 分钟逐步退避，避免不断重试；不确定结果也会延迟再检查。群聊若长期低产出，原有策略可暂停自动整理七天，页面会显示暂停时间。超过 12000 字的消息保留待拆分，不会阻塞其他聊天的正常整理。

发现过去某条消息漏记，并不意味着新版会自动修复它。可以重新完整说明事实，或在对应聊天范围手动新增，避免把第三人的话当作自己的事实。

## 8. 搜索、记忆图和回复证据

### 8.1 文字筛选与语义找

文字筛选适合知道具体关键词时使用；语义找适合表达相近但用词不同时使用。例如记忆里是“喜欢雨声”，你可以用“下雨时喜欢听什么”查找相关记录。相关分数是排序依据，不是事实正确率。

语义找主要使用本地向量模型，不单独请求聊天模型生成答案。第一次使用仍可能依赖本地模型下载及加载。

### 8.2 查看检索依据与来源

展开证据，可看到原话、来源、范围和检索信息。控制台检索属于预览，不能据此推断“刚刚那句 QQ 回复肯定用了这条”。实际回复使用情况要看会话上下文中的对应回合记录。

回合可能显示成功、失败、部分发送或状态不明。发送不明时不要把它当作已送达；“本轮不相关”的反馈绑定实际回合，不会自动删除那条记忆。

### 8.3 记忆图

记忆图把记录画成节点，把系统识别的关系画成连线。可缩放、拖动、按范围或层级筛选，并切换视图。它适合发现关联和查看分布，不应把一条连线当成真实因果关系证明。

大库会受到加载上限或分页影响，看不到某个节点不一定代表记录被删除，应回长期记忆页搜索。

## 9. 聊天原文与摘要

会话上下文入口用于查看某个聊天的原文、摘要和相关回合信息。具体入口取决于宿主的会话面板；它不一定是主页面顶部的独立标签。

原文保存说过什么，摘要把一段对话压缩成较短内容。摘要不是完整录音式存档，可能省略细节或产生误解。重要事实仍应保留可核对的原话。

需要整理时，在该会话上下文页面使用摘要入口。生成摘要会调用模型；删除错误摘要只处理摘要层，不会自动删除原文、长期记忆或撤回已发送回复。以后生成的新摘要也仍要核对。

原文层有保留条数和文本预算，长消息与过旧内容可能不完整。不能把“当前上下文没显示”直接理解为“整套系统从未保存过”。如果涉及重要纠错，提供原句、说话人和时间会更有帮助。

## 10. 轻量记忆、日记和情景记录

### 10.1 轻量记忆

“轻量记忆”包含正在聊的话题、想说但还没说的话、群友印象等。先选聊天，再查看或编辑对应内容。可以新增话题、补充尚未问出的问题，或移除过时印象。

这些内容服务于聊天连贯性，不等于长期已确认事实。添加一句“想说的话”不会立即向 QQ 发出消息，也不保证下一次一定说到。

### 10.2 公开日记

在“日记”选择公开本和日期，阅读当天记录。页面提供的编辑、补页等操作会影响日记正文。修改后可查看操作记录，确认是否提供撤销。

日记是整理和生成结果，不能仅凭日记一句话就判定你真实说过。涉及偏好或承诺时，仍应核对聊天原文。

### 10.3 私密日记

选择私密本后按页面要求解锁。当前支持查看与补页，不支持像公开本一样任意编辑全部正文。补页可能调用模型。

私密本使用加密文件，但本机管理员和持有解锁材料的人仍可能读取；不要把它当成独立于本机权限的保险箱。私密日记不会因为能在控制台查看，就自动变成所有聊天可共享的记忆。

### 10.4 情景记录

在情绪相关页面查看情景记录，包括发生的事件、系统解释、情绪、行动和结果。可以按入口补充结果或删除不合适的记录。

“解释”和“结果”可能来自模型或启发式整理，不是客观事实认证。澄清误会后，关联解释可能标记撤回，但已经发送的消息和独立日记不会自动消失。

## 11. 性格与情绪系统

### 11.1 性格与情绪有什么不同

性格是相对长期的表达底色、边界和偏好；情绪是近期事件引起的变化。一次普通请求不应让长期人格立即改变。性格页可以查看和编辑维度，按已有入口从角色卡起草、查看建议或按聊天微调。

从角色卡起草和相关合并可能调用模型。启用人格漂移时，应看清“直接应用”与“只建议”的区别：前者可能自动改变底色，后者需要你采纳。需要稳定人设时先关闭自动漂移或使用建议模式。

### 11.2 当前情绪怎样计算

系统先判断事件类型和对象，再更新短期情绪、较慢的心情及长期底色。状态随时间恢复，标签使用不同的进入和退出阈值，减少边缘状态来回跳动。标签是系统对状态的描述，不是对人的情绪诊断。

普通请求、用户诉苦、任务纠错和真实关系冲突分开处理。久未联系的轻微想念/失落也有单独上限，不应一直累加成强烈生气。

### 11.3 按需复核复杂情境

在情绪页开启“按需复核复杂情境”后，部分反讽、亲昵玩笑、澄清或高情绪消息会额外调用现有模型判断。默认关闭，沿用管理员私聊范围；不是每条聊天都调用，也没有扩大到所有群聊。

模型返回事件判断，程序控制状态变化和有效范围。每天不设复核次数硬上限，但仍有去重、有限上下文、超时和证据校验。与整理队列的每日额度无关。

模型复核失败时保守处理，不把失败当成用户恶意。有限触发器仍可能漏掉复杂表达，所以打开开关不等于所有语境都能正确理解。

### 11.4 情绪异常时怎样排查

1. 找到情绪页显示的最近起因、事件类型、对象和判断来源。
2. 对照具体原话，区分“用户说自己难过”和“用户攻击角色”。
3. 如果是误会，及时明确说“刚才那句话是引用，不是在说你”，必要时引用原消息。
4. 查看是否发生了修正；不要默认所有历史都能无限回放。
5. 记录仍不正常的原句、前后几句、时间和模型状态，便于复现。

情绪页的“联想带来的主观感受”单独展示临时印象与偏移，具体规则见第 13 章。

当前澄清只尝试修正同聊天、同说话人最近匹配事件，受约十分钟及最多十六个事件的窗口限制。窗口外或状态被手动修改后，不能保证自动重算。已经发送的 QQ 消息不会因此被撤回。

## 12. 主动联系与催睡

主动联系按空闲时间、允许时间窗、概率、日次数和冷却共同判断。到达时长只是满足一个条件，不代表立即发消息。催睡同样需要功能开启、时间条件和联系人状态等条件满足。

在情绪页相关设置中调整这些项目。先确认目标、时间和总开关，再逐步调整概率或次数；不要同时大幅修改很多参数，否则很难知道是哪项造成频繁联系。

久未联系允许有限的想念、失落或轻微小脾气。用户提前说明要忙时，系统会对部分明确忙碌表达暂停联系；这是有限模式识别，不是完整日程管理。回来正常说话会缓和久未联系的影响，真实冲突仍独立处理。

如果不希望被主动打扰，可以关闭主动联系或催睡。关闭这些功能不等于关闭正常回复或长期记忆整理。空闲联想自身不会主动发消息，也不会替代主动联系开关。

## 13. 空闲联想试验

### 13.1 联想为什么会等待

在总览找到“空闲联想 · 试验”。它仍默认关闭，只面向主人私聊：

1. 收到符合条件的新消息后，安静约两分钟才尝试生成。
2. 从同一聊天的真实记忆出发，最多两步、最多两次模型调用；两轮至少间隔三十分钟。
3. 话题保留十分钟。下一句不相关时暂存，不会重置有效期，也不会为了等话题反复调用模型。
4. 后续聊天召回了所需来源时，再单独读取原始事实，确认没有删除、替换或过期，然后准备回复参考。
5. 同一话题只准备一次。聊天模型可以采用，也可以忽略；角色不必机械地把所有想到的内容说出来。

例如：角色想到“雨天可以聊读书”。你先说“帮我看代码”，它会继续存着；几分钟后你聊到雨天阅读，仍有机会接上。十分钟后才回来则已经过期。

目前相关性仍采用保守的来源匹配：需要当前普通记忆召回覆盖话题引用的来源。它提高了等待利用率，但没有承诺所有语义相关话题都能触发。

### 13.2 去向记录怎么看

点击“查看联想去向”，可以看到话题、来源、到期时间，以及最近状态。

| 状态 | 含义 |
| --- | --- |
| 已生成，等待合适话题 | 有临时话题，还没用于当前回复 |
| 本轮不相关，继续暂存 | 当前召回没有覆盖引用来源，原有效期不变 |
| 来源校验暂不可用 | 服务暂不可用，暂不注入；有效期内允许后续再试 |
| 已准备回复参考 | 已组装参考，尚未确认投递给模型 |
| 已交给聊天模型 | 提示词请求被接受；不表示模型实际说出来了，也不表示 QQ 已发送成功 |
| 投递未接受或未启动模型 | 请求失败或转成直接命令，参考已丢弃 |
| 投递结果未知 | 无法确认接受结果，不重复注入以免重复使用 |
| 来源已变化或失效 | 引用事实已修改、删除、替换或过期，丢弃对应想法 |
| 话题已过期 | 超过十分钟，不再使用 |
| 被新消息打断 | 新消息到来，尚未完成的旧一轮生成失效 |

记录位于桥接 `state/idle-association-audit.json`，最多保存最近 40 条、读取时保留七天内记录；页面显示最近 20 条。它是本地诊断记录，不进入向量记忆库。重启保留诊断记录，但不会复活临时话题和感受。

### 13.3 “想多了”如何影响情绪

总览新增独立开关：**允许联想产生轻微主观感受（试验）**，默认关闭。要产生这种感受，需要同时开启空闲联想和情绪功能。

开启后，同一次联想调用可以附带一个主观印象，例如“也许最近压力大，我有一点担心”。它与“用户明确说自己压力大”是两种记录：

| 内容 | 保存和使用方式 |
| --- | --- |
| 用户原话支持的事实 | 继续走既有事实提取、确认和冲突处理 |
| 角色的模糊理解 | 标记为未确认，只作为临时主观印象 |
| 主观印象带来的感受 | 只影响主人私聊的轻微措辞和情绪页面的暂时偏移 |

规则如下：

- 感受类型限定为好奇、温暖、担心，不根据猜测增加冲突分或关系恶化。
- 模型给出的把握度最多记为 0.6，它只是生成记录值，不是真实准确率。
- 愉悦度偏移最多 ±0.04，唤醒度最多 +0.03；五分钟减半，十分钟失效。
- 展示时计算偏移，重复刷新不会累加；不会写入真实事件情绪、长期气候、人格或情景事实。
- 新的主人私聊消息到来，就先清除旧感受，再处理当前消息。用户解释、纠正后，不保留旧猜测继续影响语气。临时话题仍可以在有效期内等待相关场景。
- 若后续话题相关，模型可以获得一次“刚才曾想到……”的历史主观印象参考，因此有机会自然说出关心或联想。它明确标为过去的未确认印象，不会重新激活情绪偏移；当前消息、澄清和拒绝优先，不能拿旧印象反驳用户。关闭主观感受开关后，这种参考也停止提供。
- 关闭开关、关闭空闲联想或手动重置情绪，都能清除这层临时感受。
- 提示词要求不能把沉默当成“不在乎”、不能用上一步的猜测支持下一步的猜测；这属于模型语义约束，不是对模型理解永远正确的保证。数值上限、过期和不进入事实库则由代码控制。

它不额外创建主动联系任务。已有主动联系功能满足自己的窗口和频率条件时，可以读取当时仍有效的轻微主观感受；关闭主动联系不会因为联想而被绕过。

这仍是有限的短程联想，没有实现持久的自主思维或长期主观信念系统。是否自然、是否容易误解，仍需实际对话观察。

## 14. 玩梗功能

“玩梗”页用于查看可选梗库与策略。梗库是另行准备的本地 SQLite 数据，不随本插件发布；未安装梗库时，不代表长期记忆库损坏。

可按页面提供的总开关、私聊/群聊和主动候选设置控制。每轮只给少量候选，是否使用仍由模型决定；开启不等于每次都讲梗。系统对部分政治、敏感和攻击类内容有限制，但规则不能保证识别全部不合适表达。

如更换梗库，应先备份并保持兼容表结构。来源和许可见仓库 `docs/memes.md`。不要把网页显示的梗库数量当成安装包一定自带的数据数量。

## 15. 模型用量与费用

### 15.1 哪些功能需要模型

| 操作 | 模型调用情况 |
| --- | --- |
| 浏览、文字筛选、手动编辑 | 通常不需要聊天模型生成 |
| 本地语义检索 | 使用本地向量模型，不是一次聊天生成调用 |
| 自动/手动提取 | 一次提取；声明完成的消息通常再独立检查一次 |
| 遗漏续处理、失败后重试 | 可能增加请求和费用 |
| 确认/恢复事实 | 有旧事实需核对时，每批最多八条，可能调用一次 |
| 情绪复杂情境复核 | 开启且满足触发条件时额外调用 |
| 摘要、日记补页、性格起草 | 相应生成操作可能调用模型 |
| 空闲联想 | 开启且满足条件时，每轮最多两次 |

### 15.2 如何看“花费”页

“累计 · 功能花费”显示账本累计数据；“时间统计”和“所选时段 · 功能花费”跟随 24 小时、7 天、30 天按钮。

后台调用现在按入口区分：记忆提取、提取查漏、事实复核、空闲联想、情绪复核、聊天摘要、性格整理、性格草案、日记生成、图片理解，以及其他内部调用。它们仍属于“可塑性记忆”，不会再被当成角色对话。

- 分项归属与用量记录一起保存，正常完成、重连和重启不会抹掉标签。
- 升级前统一归类的记录保留为“历史未分项”，不会根据内容猜测用途。
- 功能汇总在聊天分页之前计算；较小的功能花费不会因为聊天数量多而消失。
- 趋势直接按账本内仍保留的逐次用量聚合，不再只拿最近 1,000 轮拼图。前端展示所有返回的时间桶，不再截掉前半段。
- 图中边界覆盖从查询时刻往前的完整所选时长；没有用量的时段仍显示空桶。
- 推理 token 是输出 token 的细分，按照现有账本口径，不在输出之后再重复相加。

**累计值与趋势图之和不一定相等。** 较早的记录可能只有累计快照，或逐次明细已压缩淘汰。它们仍保留在累计金额中，但无法可靠地分配到某个时间点。页面会提示明细限制，不把历史累计值伪装成今天的消费。计费用量记录数包含重试，也不等同于成功完成的整理批次。

费用按当前配置的模型价目表估算；模型没有返回 usage、超时后未收到用量等情况不能靠本地账本推算出真实账单，最终以服务商账单为准。

### 15.3 怎样控制消耗

优先限制不需要的聊天范围、关闭不需要的试验功能，再设置自动整理批次额度。频繁手动整理或重试会额外消耗。确认大量历史前可以观察进度并停止后续批次，但已经发出的请求可能仍计费。

不要把“每天不限”理解为每轮都应调用。情绪复核、整理额度和主动联系次数分别控制不同流程。

## 16. 备份、升级和回退

### 16.1 备份哪些内容

| 内容 | 常见位置 |
| --- | --- |
| 长期记忆、原文、摘要、复核页进度 | `~/.dsh/memvec/memories.db` 及相关 WAL/SHM |
| 待处理队列和桥接状态 | `~/.dsh/qq-bridge/state/` |
| 桥接配置与主动联系设置 | 桥接 `config.json`、`owner-contact.json` |
| 性格、情绪、审计与私密日记等 | `~/.dsh/feiyu-memory-console/` |
| 公开日记 | `~/.dsh/whale-diary.md` |
| 程序与回退材料 | 旧插件源码、独立 `server.py`、桥接 `src/` 和 `.runtime-backups/` |

以实际路径为准。先停止写入相关服务再复制完整数据，或使用 SQLite 在线备份。运行时只复制一个 `.db` 可能遗漏尚在 WAL 中的数据。

### 16.2 升级顺序

下载同一版本的包和升级指南 → 备份 → 退出 DSH、桥接及记忆服务 → 更新插件 → 检查并更新桥接运行时 → 更新独立 memvec 源码 → 重启 → 核对版本、服务、队列和已有事实。

退出 DSH 窗口不一定停止独立 node/Python 服务。需要确认端口和对应进程；不要按程序名结束全部 node 或 Python 进程，它们可能属于其他应用。

### 16.3 回退的范围

停止桥接后，用本次安装所用版本的安装器执行 `--undo`，只恢复它管理的运行时文件和回执。插件源码和 memvec 源码需另外恢复。

回退数据库会丢失备份之后新增的内容，不能把旧数据库直接覆盖当前库当成常规降级。先保留当前完整副本，再明确需要恢复的范围。程序回退与数据回滚是两件事。

## 17. 常见问题与排查

| 现象 | 优先检查与处理 |
| --- | --- |
| 更新后仍显示旧版 | 重启 DSH、刷新网页，检查实际加载的插件目录 |
| 突然变成零条记忆 | 查数据库路径是否变了，不要先删除或重新导入 |
| 记忆服务离线 | 检查 Python 环境、依赖、模型下载和端口 9881 |
| QQ 能聊但长期记忆不更新 | 检查 memvec、整理总开关、会话范围、队列和模型调用 |
| 群聊没有入队 | 默认需要 @/回复；检查群聊参与策略及授权范围 |
| 队列停着不动 | 看重试原因、额度、低产出暂停、超长消息和服务繁忙 |
| 已检查但没有新增 | 可能是闲聊、重复、转述或被排除；重要内容对照原话 |
| 显示提取时待确认，列表找不到 | 选对聊天和状态；记录可能后来已确认、删除或过期 |
| 八条之后继续复核很慢 | 每批都可能请求模型；查看进度，必要时停止后续检查 |
| 一直提示历史变化 | 检查同期是否编辑或新增了相关事实，稍后重试 |
| 喜欢 A 与不喜欢 B 被说成冲突 | 比较对象、条件和原话，确实都成立时选择分别保留 |
| 记忆正确但回复没用到 | 检查检索范围、预算与实际回合，不只看控制台预览 |
| 情绪突然变差 | 核对事件类型、对象、原话及复核来源，及时澄清 |
| 空闲联想没有内容 | 检查开关、主人私聊、新消息、空闲时间、冷却和模型 |
| 摘要或日记写错了 | 在对应层处理，不能假定删除摘要也会删掉长期记忆 |
| 无法撤销 | 后续数据可能变化，或该操作不支持撤销；先查看审计 |
| 安装器拒绝覆盖 | 存在未知版本、自定义修改或回执问题，先备份与比对 |
| 刷新后按钮还不可用 | 桥接能力未更新或后端未重启，只换网页不够 |

反馈问题时附版本、涉及页面、操作步骤、期望和实际结果。若涉及语义错误，提供去除私人信息后的原句和必要上下文；不要上传整个真实数据库、密钥或控制令牌。

## 18. 配置速查和使用边界

优先使用网页设置。必须修改配置文件时，先备份并理解该文件的加载方式；不要在服务频繁写入状态时随意覆盖状态文件。

| 配置 | 当前含义 |
| --- | --- |
| `socialV2.dailyMemory.enabled` | 整理功能开关；关闭后不收新队列消息 |
| `socialV2.dailyMemory.maxCallsPerDay` | 自动成功整理批次额度，默认 0 为不限，旧值保留 |
| `socialV2.dailyMemory.groupMaxCallsPerDay` | 群聊成功批次额度，默认 20，0 为不限 |
| `socialV2.dailyMemory.queueMax` | 每个聊天队列容量，默认 5000，0 为不限 |
| `socialV2.dailyMemory.groupPolicy` | addressed / semantic / signals / off，默认 addressed |
| `socialV2.emotion.appraisalModel.enabled` | 可选复杂情绪复核，默认关闭，按需触发 |
| `socialV2.association.idleEnabled` | 空闲联想试验，默认关闭 |
| `socialV2.association.idleAffectEnabled` | 联想产生轻微主观感受，独立开关，默认关闭 |
| `socialV2.memoryShare.enabled` | 跨聊天共享，默认关闭 |

默认值是新配置的基线，不代表升级会重置你的设置。模型能力、延迟和费用依赖实际服务；本手册没有承诺零误判、零遗漏或人类式情绪理解。遇到重要事实，以可核对的原话和你的明确决定为准。

更多技术信息参见仓库 README、UPGRADE.md、CHANGELOG.md、docs/complex-emotion.md 与 docs/memvec.md。
