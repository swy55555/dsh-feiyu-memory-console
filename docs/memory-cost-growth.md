# 记忆增长、会话与审核费用

适用：0.10.1。2026-10-31 更新，未发布。

## 存得多是否每轮都更贵

数据库不会整库发送给聊天模型。本聊天默认召回3条；自然记忆参考最多4条、正文预算1200字符，主人私聊的综合关注参考共用2400字符预算；历史原文和摘要默认分别有6000与2000字符预算。字符不是 token，标题、人设、工具说明和会话累积历史另计。

新会话不会自动继承所有旧会话全文，但会重新加载基础指令和有限参考。频繁轮换也可能增加摘要与重复加载开销，不能仅凭会话个数推断账单。

## 本次调整

1. 按单条关系复用回执。页内只有一条新增或修改时，只送这一条，不重送另外七条。缓存仍按聊天、候选原文、旧事实版本和操作隔离；人物、原话或事实变化会失效，读取计数不会使它失效。
2. 自动审核遇到原话不支持、关系不确定或冲突时，保存进度并转为待人工核对，不继续付费扫完剩余历史。用户手动点击仍可继续；没有核对的部分不会被视为通过。依赖变化后可重新检查，已有有效回执仍复用。
3. 先检查显式关联，再按同对象同属性及语义相似度排序。提取出的结构只影响顺序，不充当事实证明；没有结构或相似度较低的事实仍保留在审核范围。
4. 最终自动确认仍要求完整原话通过、全部现行关系齐全且安全，并在事务内核对完整集合版本。并发变化、缺项、跨聊天回执和过期结果不能绕过检查。人工明确处理冲突的流程保留。

“自动核对暂缓，可手动继续”表示系统已发现不能自动确认的原因，不是数据丢失；尚未检查完时显示已复核数量。

## 为何没有直接只审最相似的8条

本机用现有本地向量模型，对12组合成冲突和每组32条干扰事实做了检索冒烟测试。在“不喝任何含咖啡因的饮料”的情境中，“每天喝含咖啡因的美式”被排到第20位，截断前8条会漏掉它。

这是人为构造的反例，不是实际用户总体漏检率。阈值0.35在该小样本没有漏检，也不足以支持生产环境据此跳过历史。因此默认仍不启用缩小全集的策略；本版提供可选 related 模式，边界见文末说明。之后若引入更完整的结构化索引和语义扩展，应使用另留的标注集、跨表述和时间条件反例评估，并保留不确定时完整审核的路径。

## 验证和限制

同一份离线场景：原先新增1条事实会重送7条旧关系；现在发送1条新关系、0条已审关系。该场景仍需要一次模型调用，节省的是输入、输出内容，不能把8到1解释为总费用降低87.5%。本次检查和模拟没有付费模型调用，没有向真实记忆写入模拟事实。

所有依赖都新、原话通过且最终需要完整确认时，全部关系仍必须核对：同一聊天同一人物43、100、1000条有效事实分别需要最多6、13、125页首次关系审核。早停和缓存降低重复与无效工作，没有把首次完整审核变成固定成本。实际节省应按新增候选数量、处理状态和账本比较。

测试覆盖单条变化、页排序变化、回执重开复用、遗漏/过期/跨操作拒绝、原话不支持早停、部分不确定早停和手动继续。旧版完整分页回执仍可读取；最终确认门槛没有降低。


## 可选审核范围

本版保留默认全量审核，也提供显式开启的相关范围模式：审核选入的同方面事实和少量语义近邻，可能漏掉范围外冲突。页面显示的“审核通过”仅指当前选定范围；原话、有效期和版本检查仍保留。详见[配置与限制](review-scope.md)。此模式不等于所有候选自动生效。
