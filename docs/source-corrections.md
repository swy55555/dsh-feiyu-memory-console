# 来源纠正联动：第 1E 项基础

2026-11-01 已完成本机差异安装与运行验收，未发布新版本。运行服务能力为 `source-correction-v1`；其他安装环境仍应核对自己的安装回执。

## 解决什么问题

当一句原话本身说错时，仅修改一条提取结果，其他摘要、认识和自我参考可能还在引用它。现在可以撤回这句原话的**依据资格**，让明确依赖它的参考暂停使用。原话作为历史仍保存，不改写聊天记录，也不凭空创造一条“正确事实”。

这不是新的日常确认队列。正常记忆维护继续自动进行；只有需要明确撤回整句依据时才使用这个入口。如果只是模型提取错、其中某一小点有误、或者后来偏好变了，应修改具体记忆，不能把整句原话都判为无效。

## 使用入口

记忆卡片 → 查看记忆来源 → **原话说错了：撤回依据或查看撤销**。

先查看将暂停的记忆与摘要，填写理由，勾选“撤回整句原话的依据资格”，再提交。此确认仅针对整句撤回这一管理操作，不要求逐条确认普通记忆。来源不完整、被截断、归属或原话版本无法核验时不能提交。

提交后，受影响的有效记忆和候选、摘要会归档，退出正常检索。可在“已归档”中找到记忆，从同一入口撤销纠正。普通“确认”或“恢复”不能绕过已撤回的来源；更换为经核对的新依据后才可继续按原流程处理。

## 心迹如何联动

心迹在后续组装参考时读取本地纠正状态，按聊天范围和来源事件编号排除相关挂念、认识、回应反馈、临时表达要求、自我参考。含有已撤回证据的整条认识保守暂停，不擅自凭其余证据重新宣布成立；原有记录和历史保留。相关页面会显示“来源已撤回，暂停使用”。

事件理解与自我参考整理在运行中遇到来源有效性变化时，不提交旧结果。被撤回的自我参考队列输入不会再触发该模块的整理调用。读取有效性失败时，暂不使用有来源的相关参考，避免把读取失败当成“来源都有效”。

记忆 → 联想路径继续复用已有投递前本地复核；来源撤回使记忆归档后，旧联想失去可用父记录，不再按原来的有效记忆投递。已产生的心情、性格和关系数值不机械倒退。

## 版本、撤销与历史

- 提交需要同聊天、同作者、同原话版本及当前依赖快照。相关记忆在预览后发生变化时拒绝提交，要求重新预览。
- 数据库内暂停与纠正记录在同一事务完成，失败整批回滚。SQL 约束也覆盖控制台直接更新和迟到的记忆/摘要写入。
- 撤销只恢复仍与暂停后版本完全一致的条目；后续编辑、删除、其他来源失效或版本变化都会让对应条目保持现状，并报告跳过数量。
- 撤销不会覆盖心迹后来的状态文件；只是取消来源屏蔽，由当前状态、期限和其他规则决定是否重新可用。
- 纠正历史保存原因、版本和处理数量。原始证据因纠正记录继续保留；普通归档、删除单条记忆不等于隐私彻底擦除。全会话擦除及备份清理仍需单独实现。

## 本阶段明确未覆盖

没有自动把聊天中每一句新说法都当成纠正，没有额外全库模型审核，没有自动重写全部相关结论。后续 1F 已实现复用主人私聊现有事件理解来处理近期明确的整句撤回，范围及安装验收见[聊天澄清联动](chat-clarifications.md)。不新增独立纠正模型；局部纠正、后来变化、远期来源和不确定情况不因此自动撤回整句。

已经交给模型的旧上下文、尚未登记的间接派生关系、旧轻量便签、课程和数值人格等，不能据此宣称已全链清理。后台其他模块已排队的旧提取工作可能仍到达写入边界，被本地约束拒绝；统一调度和费用复用属于后续阶段。被归档但后来手动修改的记录，撤销时不会自动重新激活。

页面查询、预览、提交、撤销和本地参考筛选均不调用语言模型。

## 验证方式

新增测试覆盖：实际 HTTP 管理入口、来源及人物/聊天隔离、检索和摘要暂停、缓存清理、重复提交、过期快照、事务失败回滚、直接 SQL 恢复拦截、撤销不覆盖后续编辑、来源窗口淘汰后保留、心迹实际提示词筛选、运行中结果失效，以及页面明确操作、错误反馈与撤销。

真实库只做一致性备份，在隔离副本上迁移、撤回和恢复；对比原话、记忆、摘要的内容校验，不向真实 QQ 发送测试消息，不调用付费模型。

本次 57 组回归通过，新增 8 项数据库测试和 5 项心迹来源屏蔽测试，页面测试通过；隔离副本抽查 20 个来源、暂停并恢复 40 条关联记录，三类原始记录的校验值恢复一致。运行端本地预览、页面入口和数据完整性通过验收，真实库没有写入测试撤回记录。

## 回退

部署前保存文件备份和 SQLite 一致性备份。未执行过撤回时可回退相关代码；一旦已经执行，先在当前版本核对并撤销需要恢复的来源。不能只换回旧桥接而宣称跨模块屏蔽仍有效，也不能删除纠正表绕过约束。不要用整库旧备份覆盖安装后新产生的聊天。
