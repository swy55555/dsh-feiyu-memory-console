# 理解交流需求

适用版本：0.11.1。此页说明当前交流理解的作用与边界；完整系统结构见 [技术手册](TECHNICAL_MANUAL.md)，本轮验证见 [发布验证记录](RELEASE_VALIDATION.md)。

## 解决什么问题

同一句“你没懂”或“不聊了”，需要结合双方刚才的表达理解。系统从符合权限的同一会话原话中提取当前意图、回应重点与暂停边界，把结果作为本轮参考。它可以帮助区分分享、倾诉、求助、澄清和修复误解，但不保证模型真正理解了用户。

理解不等于赞同。既有六维与自我参照提供表达背景，当前明确反馈优先于过去偏好；不能为所有人预设统一的温柔、打趣或挽留方式。有歧义时保留不确定性，不将隐藏动机猜测写成事实。

## 输入、校验与投递

1. 从同一会话收集带说话人和消息 ID 的双方原话窗口，限制时间、条数与字符数。历史用于解释当前交流，不自动成为新增成长证据。
2. 连续事件理解在已有的一次分析中同时产生情绪、挂念、认识和交流理解。各部分分别校验；部分无效不能连带放宽其他部分的写入条件。
3. 核对当前原话、历史消息 ID、说话人与逐字引用。需要修复之前回应时，必须能指向实际角色发言；模型置信分不是准确率。
4. 通过校验的交流理解进入已有关注预算。预算不足、过期、消息替换或会话不允许时，它可能不进入聊天上下文。
5. 根据通过校验的类别附加程序定义的回应重点，不把模型生成的自由文本提升为高优先级指令。指导与对应理解一起计入预算，不能在原理解失效后单独残留。

主要实现位于 `interaction-context.mjs`、`continuity.mjs`、`mind-workspace.mjs` 及桥接接线。分析收到参考、参考被投递、模型表达正确是三件事；应分别看审计与实际回复。

## 开关与成本

交流理解依赖连续事件理解及其会话权限。关闭后普通聊天继续自身流程；其余记忆、情绪复核和自我参照有独立开关，不能据此推断所有后台调用已停止。

联合生成可复用已有分析，不代表增加字段和上下文没有成本：输入输出 token 仍可能增加。结果失效与超时可阻止应用，不能撤回服务商已经产生的费用。具体操作和关闭方式见 [用户手册](../manual/USER_GUIDE.md)。

## 失效与隐私边界

理解是有时效的本轮参考。新消息、相关配置改变或来源失效后，不应继续当成当前需求；较早任务的迟到结果不能覆盖新一轮状态。重启后的历史审计也不等于可直接复用的当前理解。

管理员私聊的私人经历不能因共用角色或模型而进入其他会话。需要区分管理员、其他私聊和群聊的允许来源；不通过补填旧记录来猜测原说话人。

## 如何判断是否有效

检查四件事：是否理解当前明确诉求，是否引用相关双方原话，是否具体回应内容，是否尊重当下偏好与边界。只通过 JSON 或引用校验、只给出漂亮的自我评分，都不能证明交流质量。
