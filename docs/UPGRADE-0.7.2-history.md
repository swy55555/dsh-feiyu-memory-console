# 升级到 0.7.2 本地优化版

此包由提供的 0.7.1 源码修改而来，未发布到 npm；不是原作者的正式发布声明。

如果已安装上一轮 0.7.2，本次只需升级 bridge 补丁，按下文安装器步骤操作，再正常重启 QQ 桥接；无需重新导入或迁移记忆，也无需因本次桥接修订再替换 memvec。下方完整升级步骤适用于尚未完成最初 0.7.1 → 0.7.2 升级的安装。

## 已安装用户

1. 停止 DSH 中的插件和独立 memvec 服务，备份现有数据。优先在服务停止后备份整个数据目录，保留配置、数据库、日记、审计和私密日记所需的密码文件。
2. 用本包代码更新插件。只替换代码文件，不删除现有 `memories.db`、`hfcache`、`.venv`、桥接配置或日记。
3. 找到实际运行的 memvec（它可能位于 `~/.dsh/memvec`，与插件内附带源码不同），更新其 `server.py`。不只更新插件目录中的副本。
4. 在插件目录执行 `npm run doctor`。确认数据库路径一致。自定义库需要同时设置 `MEMVEC_DB_PATH` 和 `FEIYU_MEMVEC_DB`，两个进程都应继承相应环境变量。
5. 重启 memvec 和 DSH，刷新首页检查。没有桥接时，桥接和 QQ 检查失败是预期的，记忆服务仍可单独使用。

新增的 `memory_operations` 表会自动创建，原有 memories 数据保留。确认记录包含受影响记录的状态快照及校验指纹；完整确认与操作记录在一个 SQLite 事务中提交。控制台的 JSONL 审计是独立的界面索引，不与 SQLite 跨文件原子提交；即使 JSONL 写失败，数据库仍保留确认操作记录。数据库操作记录不会自动清理，需随数据库一起备份。

## 行为变化

- 群聊“全部确认”只确认该说话人的候选。冲突导致整个批次失败，先处理冲突再重试。
- 确认撤销会恢复旧事实、新候选、取代指向、核心层级和期限。任何关联记录后续发生变化，或出现新的冲突事实，均拒绝撤销。
- 旧版确认记录缺少必要快照，不支持安全自动撤销。其他既有操作的撤销机制保持原样，不应理解为本次已重写所有类型的撤销。
- memvec 的 search_memory 召回当前聊天及 global 的活跃、未过期记忆，恢复原有全局记忆行为。控制台搜索仍按自身筛选范围展示，且不允许直接确认 global 候选。
- 单次搜索采用统一的最低匹配分 0.28；分数不是事实正确概率。私聊/群聊筛选限制服务请求范围。
- 直接运行 `python memvec/server.py` 仍保留旧的同目录数据库默认行为；推荐使用 `npm run start:memvec` 以对齐控制台路径。

## 本版边界

“查看检索依据与来源”展示的是控制台搜索时的真实结果、评分与存储的来源片段，不宣称某条 QQ 回复实际引用了这些信息。来源片段可能被原提炼流程截断。

原压缩包没有 QQ 桥接源码；后续在本机找到桥接，新增了独立的 `bridge/` 补丁，接入实际提示组装。完整的逐回复采用追溯、提炼类型区分、日记推测隔离、情绪跨聊天影响及人格默认策略仍未全面实现。

未在真实 QQ 账号、SnowLuma 或生产桥接上联调，也没有用真实 embedding 模型做召回质量评测。回归测试使用确定性向量，验证状态、范围、事务、接口和 UI 行为。

## 研究启发的对话上下文补丁

先看 `bridge/RESEARCH.txt` 和 `bridge/EVALUATION.txt`。这是可评测的工程方案，并未证明本插件的真人感改善。插件版本维持 0.7.2。

在本包目录执行 `node bridge/install.mjs --target <QQ桥接目录> --check` 检查兼容性，然后用 `--apply` 安装。安装器逐处核对原代码，遇到不匹配就停止，备份原文件至桥接目录 `.human-context-backups/` 并写入安装回执。不会修改配置/数据库、启动进程或发送消息。正常重启桥接后启用。

新模式默认启用；在已有配置的 `socialV2` 对象内合并 `"humanContext": { "enabled": false }` 可切回原上下文及随机提示，不要覆盖整个配置文件。可选 `maxChars` 默认1200（范围600—2400），`maxItems` 默认4（范围1—6）；都是工程参数，不是研究最优值。

从已登记的上一轮补丁升级时，安装器会核对旧回执中的桥接和模块哈希，并分别备份它们及旧回执；手工修改过的文件不会自动覆盖。撤销升级会一起恢复这三个文件。

完整撤销用 `node bridge/install.mjs --target <QQ桥接目录> --undo`。仅当安装后桥接和模块都未再被修改时才自动恢复；原始字节校验一致，已存在的备份保留。之后正常重启桥接。

本次上下文模块不生成情绪值，不推断待办完成，不增加自动发消息或定时任务；跟进限制是提供给模型的规则，不能保证模型不会重复追问。默认预算只包含新增上下文，不包含角色卡、最近聊天、工具等整个提示。
- `npm run doctor -- --json`：输出依赖、记忆服务、数据库、版本能力、桥接和 QQ 状态；有待处理项时退出码为 1。

测试中的 Python 可通过 `FEIYU_PYTHON` 指定。旧 UI 测试不在默认测试集合中，且要求显式允许写入测试实例。
