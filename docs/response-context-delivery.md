# 连续聊天中的参考更新与历史语境

## 已确认的问题

2026-11-01 的争执记录中，39 次等待工具返回了新消息，但没有对应的新心绪或回应要求。唤醒提示只在部分时刻重新组成，因此“后台理解了”不等于“后续聊天请求收到同一份理解”。当时的自动召回还包含“骂我就好”等独立旧话，缺少前后的条件；可选梗和发空间建议也进入了认真交流。

## 本次实现

1. 主人私聊的等待、读取未读、读取最近消息工具增加 `replyReference`。只读已完成的事件理解、当前情绪和仍有效的明确要求，不发起新模型调用。仅在本批最后一条实际交付的来信编号、最新序号、理解编号一致时返回完整参考；旧页、并发的新理解、重启后未恢复的临时理解和两分钟后过期的理解都不能冒充本轮状态。没有匹配参考时明确标记 unavailable，提醒以新原话为准。
2. 参考只向当前主人私聊自己的有效代理令牌提供。跨聊天转达权限不允许读取这份私人理解。感受不匹配当前消息时省略；引用其他人的整体心情不带他人的事件原话。现有工具序列化保留新字段，无需覆盖用户自定义 QQ、语音或唱歌适配器。
3. 当已有语义判断为交流反馈时，对最多三条同聊天召回记录读取原话附近的短窗口。核对消息编号、说话人和原话完全匹配后，才附加上下文。不截断句子，不推断未知说话人；找不到、已纠正或读取失败，明确保留不可用状态。此类反馈场景暂不自动注入缺乏原情境的历史召回，也暂不自动注入旧轻量印象；原数据不会删除。普通检索保持原有行为。
4. 原始记录的邻近聊天不会因跨聊天共享授权而一起共享。共享记录没有本聊天的原情境时，也不会借机访问源聊天。历史许可仍是历史材料，不变成本轮必须执行的行为。
5. 当前语义为反馈、求助、任务、暂停或结束时，停止附加随机媒介、发空间和梗建议；主人私聊开启事件理解但未获得判断时也不猜测。已识别的分享、玩笑仍可获得建议，工具本身不移除。群聊及其他私聊尚无同等的连续理解分类，保留原有行为，不宣称已经覆盖这些场景。

## 成本与限制

没有新增模型调用或后台学习。已识别的反馈场景最多增加三次有界本机消息读取，不需要 embedding 或语言模型；当前参考约束在 1800 字符预算内，另有短元数据。读取参考与补历史语境会占用聊天输入，不能宣称零 token；跳过不相关建议则减少另一部分输入。

本次没有自动压缩或删除真实聊天历史，没有删改人设、人格、偏好或旧记忆。旧轻量记录仍可在管理界面查看、按明确需要查询；这里只调整自动注入。没有给每句话加润色模型，也没有自动切换聊天模型。

## 验收结论

专项覆盖新旧消息版本、过期理解、跨聊天转达权限、模型调用次数、原话与说话人匹配、源记录改变、读取失败、预算和原数据保留。真实本机原话窗口可以找回“骂我就好”前的条件性对话。

两次新增离线试写使用现有 deepseek-flash / high，合计六条回复。它们是无工具后台预设下的角色续写，当前语义参考来自人工标注的测试情境，不是实时 QQ 全链路；不能替代真实聊天验收。对“失望不是操控”的回应较贴题，但表达投入落空的场景仍出现归责用户或自我解释，未通过自然表达验收。

因此，本批交付目标是修复已确认的参考传递与历史语境问题；不能据功能测试通过宣称汇报腔已经解决。后续应在这些问题修复后，再进行同条件聊天模型对照和真实工具链的隔离验收，而不是继续增加禁用句式。
