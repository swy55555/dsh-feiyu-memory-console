# 参考组装、轮换诊断与后台成功结果复用

2026-11-01 已安装并完成运行验收。61/61 组回归通过，网页深浅色和窄屏检查通过。本次为分阶段优化的基础实现，没有发布新版本。

## 正常使用

继续正常聊天，不需要逐条确认记忆。“会话上下文”页新增“参考与调用诊断”，读取页面不会调用语言模型。它分别展示最近一次参考组装、投递接受结果、轮换阻挡原因和后台成功回执复用情况。没有记录时不会伪造数据；旧桥接或诊断暂不可用不会阻止查看原文和摘要。

## 统一参考组装

主人私聊、其他私聊和群聊均经过同一入口。原有共享权限、来源核验和人物筛选不变。摘要、窗口前原文、检索记忆、共享经历及心绪参考由统一组装器安排，默认字符预算 8000。它只负责本次新增的生成参考，不是整个模型上下文的上限，也不是 token 上限。

当前请求、工具权限、完整自然表达规则和自我参考保留。已有重要记忆块、当前心绪/纠正参考完整保留，必要参考超过预算时明确报告超出，不强行截断。剩余预算用于完整的近期原文或摘要条目；不会截掉句尾的“不”“只有周末”等条件。较低优先级联想超预算可不选入，原记录仍在。

同一聊天、同一用途、同一版本且文本完全相同的块才可去重。语义相近、同一来源的不同事实、不同人物/日期/否定/条件不据此合并。本阶段尚未统一各模块内部所有条目的语义去重，不会因为“看着差不多”就删除证据。原有局部预算仍保留。

配置：`socialV2.context.unifiedReferences` 默认开启；设为 `false` 退回原组装。`referenceBudgetChars` 默认 8000，可设 2400–16000。预算、未选入字符和复用字符不换算成节费百分比。既有历史仍可能占用输入与缓存读取费用。

## 为什么会话很长却没换

本次增加观察，未强制缩短人格或强行中断会话。原有轮换条件仍是累计投递轮数或单次输入 token 达到触发值，且能够安全保存摘要和退役旧会话。

诊断会区分：消息队列未清空、模型处理中、回复收集中、工具等待、待处理唤醒、未读消息、最近一分钟仍有互动；并展示摘要失败退避、摘要期间出现新消息等情况。达到默认约 96000 输入 token 或 40 次投递不等于立即换会话。历史账本采样值不能简单视为本次记忆插件注入量。

## 后台成功结果怎么复用

当前仅接入记忆提取与独立查漏，不增加或取消模型判断环节。成功结果写入桥接状态目录 `analysis-receipts.db`；不把回执当已确认事实，不修改记忆数据库的确认条件。

匹配键包含任务目的、聊天范围、完整提示词摘要、原话/相关记忆依据、来源撤回版本、模型和推理配置。提示内容包含规则与结构版本；这些改变后重新处理。完整提示和密钥不写入回执，但结构化结果含原话摘录，仍属于私人状态文件，应与聊天数据库同等保护。默认最多 128 项，单结果不超过 256 KiB；成功复用期限为创建后 24 小时，命中不续期。过期或容量淘汰在后续任务处理中执行，不能把有效期说成准时物理删除。

成功复用后仍重新校验结构、人物和原话，并检查来源有效性。即使结果已保存，写入记忆失败也不会把队列当已完成；下次可以复用成功分析后重试写入。另一人物或聊天不可混用。

同一进程同时请求同一任务会等待同一个结果。跨进程发现运行中回执不擅自再次提交。请求可能发出但连接中断、进程中途退出等情况会标为结果不明，暂停涉及原话的自动重试，新消息继续处理。用户手动重试可能再次计费，页面与队列说明这一点；本功能不能找回供应商尚未返回的结果，也不宣称实现分布式恰好一次计费。

模型已返回但结构不合格的结果不会复用为成功，按既有队列退避再试；查漏为“不确定”也不缓存为成功。回执文件不可用时暂停相关后台提取，保留原队列，聊天继续。

## 验收范围

离线检查覆盖人物/时间/否定/条件区别、当前原话不裁剪、精确重复、整体预算、实际组装入口、轮换阻挡、管理权限、重启复用、失败写库、独立查漏、未知结果暂停及新消息不被阻塞。真实数据库只读回放仅评估参考长度与保留情况，不冒充模型语义准确率。

不在真实聊天中发送测试消息，不为此增加付费模型调用。要比较真实费用，需要后续同类聊天的请求输入、缓存命中、输出、调用数以及回复质量；不能用字符变化直接推算节省比例。

## 回退

统一参考组装可用上述配置关闭。后台复用回退需在任务空闲时恢复本次安装前的 `daily-memory.js` 和桥接入口；保留回执文件以供审计，不清空原记忆或队列。结果不明的原话不会因移除回执而自动证明未花过钱，需先核对再手动重试。
