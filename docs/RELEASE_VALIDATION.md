新增的隔离运行验收脚本为 `test/first-install-integration.mjs`。它要求显式传入从发布包初始化并执行 npm ci 的测试桥接目录，且目录内必须有 `.allow-isolated-release-test` 标记；脚本会更改该测试目录、创建模拟 Profile 并启动测试进程，**不得指向生产安装**。它不下载依赖，也不连接真实 QQ 或模型。

原 0.11.1 的 16 个浏览器测试文件曾全部通过；本版未修改页面代码，没有将旧结果冒充为本轮浏览器重测。完整回归中的运行时检查夹具已更新，因为检查范围从单一适配器的直接导入扩展到三个 MCP 与间接导入。

## 依赖修复来源

首次审计发现旧锁定的 MCP SDK 1.30.0 与 Zod 4.4.3 有高危公告，因此新安装改用修复版本并重新执行打包产物启动与 MCP 验收。参考 [MCP SDK 会话任务公告](https://github.com/advisories/GHSA-22jm-h49p-29qw) 和 [Zod 资源消耗公告](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)。本项目使用 stdio MCP，不代表公告涉及的所有 HTTP/OAuth 使用方式都能在本项目中触发。

已有桥接升级只更新受管理源码，不自动改写用户的 package.json 或 node_modules；应单独核对并更新依赖，再做 MCP 兼容性验收。

## 必须保留的适用范围

0.11.2 修复的是本项目首次安装分发不完整：原先缺少的基础模块、MCP、npm 清单/锁文件、预设与注册步骤现在随包提供。DSH 软件、SnowLuma 登录程序、真实账号、模型额度、Python 环境与模型缓存仍是外部部署条件。

本轮没有完成真实 DSH 宿主升级兼容、真实账号端到端发送、长期在线稳定性、首次 Python 模型下载或独立人工标注的语义准确率评估。模拟 DSH 故意返回不可用，验证的是桥接能独立启动并保护管理接口，不是声称模型会话已成功。新用户仍须按 [INSTALL](../INSTALL.md) 分阶段验收。

多文件状态更新并非统一数据库事务，费用估算也不是供应商消费上限。旧 Git 提交和旧 Release 附件不随新版本自动消失；本记录不代表公开历史已清除。
