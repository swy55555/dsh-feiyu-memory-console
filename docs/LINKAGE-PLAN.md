# 回响 · 模块联动计划（基于意识科学与 AGI 研究的工程参照）

> 2026-11-02 · 设计文档，不是“她有意识”的声明。
> 原则：只借用**可检验的机制描述**，不借用“意识”这个结论；所有联动必须有数据出处，没有出处就不画线。

---

## 0. 边界

- 意识科学目前没有公认理论。GWT、预测加工、自我模型等是**竞争性框架**，不是事实。
- 本计划把它们当“信息架构的参考”，用来回答三个工程问题：
  1. 哪些信息应该在**每一轮回复前被同时拿到**（广播）；
  2. 哪些信息应该**慢一点变**（性格），哪些应该**快一点变**（情绪）；
  3. 她怎么知道“自己记得的东西可不可信”（元认知）。
- 不做：不声称主观体验、不把参数叫“意识水平”、不用“她感到”去包装日志。

---

## 1. 参考框架与对应模块

| 框架 | 核心机制 | 对应模块 |
|---|---|---|
| 全局工作空间（Baars / Dehaene） | 信息被“广播”后才能被多个系统同时使用 | 每一轮的上下文装配：目标、挂念、情绪、检索记忆、叙事 |
| 预测加工 / 主动推断（Friston / Seth） | 大脑在预测输入，误差驱动学习与行动；情绪是身体状态的推断 | 潮汐（情绪=预测误差与调节）、余音（未解决的误差）、探索（主动获取信息） |
| 自我模型理论（Metzinger） | 一个关于“我此刻是什么状态”的模型 | 轮廓（慢变量）+ 潮汐（快变量） |
| 自传体记忆与叙事身份（McAdams） | 人用故事把经历连成“我是谁” | 回廊（情节）+ 叙事（阶段总结） |
| 元认知与来源监控（Flavell / Johnson） | 知道“我记得”和“我相信”是两件事，能标出来源与置信 | 拾光（来源、置信、暂定/确认） |
| 互补学习系统（McClelland） | 海马快速记单次经历，皮层慢速抽统计规律 | 回廊（快）+ 轮廓/兴趣/认识（慢，需巩固） |
| AGI：记忆中心智能体 | 检索增强、反思、世界模型、持续学习 | 整条链路：编码 → 巩固 → 检索 → 反思 → 探索 |

## 2. 一个闭环（这是联动的骨架）

```
对话
 │ 编码
 ├─ 回廊：episode（原始经历）
 ├─ 潮汐：这一轮的情绪偏移
 ├─ 余音：未解决的事 / 对人的新认识
 └─ 拾光：可验证的证据（来源、摘录）
 │ 巩固（夜间/低频）
 ├─ episode → 兴趣（taste）：多次独立来源才升级
 ├─ episode → 自我记忆（self-memory）：带摘录、带置信
 ├─ concern → 认识（belief）：有证据才改
 └─ 反复出现的行为 → 轮廓（性格慢漂移，有上限）
 │ 广播（每一轮回复前）
 └─ 全局工作空间：目标权重 + 活跃挂念 + 当前情绪 + 检索记忆 + 叙事
     └─ 写入 broadcast-trace（这一轮到底用了什么、为什么）
 │ 元认知
 └─ 来源标注、置信度、冲突检测（新旧记忆矛盾时标出来）
 │ 探索
 └─ 好奇心驱动 → 拾光 → 新证据 → 回到编码
```

**关键点**：广播不是“把所有东西塞进 prompt”，而是**有选择、有记录、可复盘**。拾光页展示的就是这条 trace 的证据侧。

## 3. 数据模型（让联动有依据）

### 3.1 统一引用

所有可展示的证据条目增加 `refs`：

```json
{
  "id": "taste-xxx",
  "topic": "手工木工",
  "refs": {
    "episodeIds": ["4282b1ef-0f6"],
    "concernIds": [],
    "selfMemoryIds": ["self-a03e8200"],
    "goalIds": ["curiosity"],
    "sourceUrl": "https://...",
    "verified": "verbatim"
  }
}
```

- `episodeIds`：这条兴趣/记忆来自哪几段对话或探索；
- `verified`：`verbatim`（逐字可核）/ `paraphrase`（转述）/ `unverified`（模型印象）；
- 没有 `refs` 的条目，拾光只显示内容，不画“相关”。

### 3.2 广播记录

`state/broadcast-trace.jsonl`，每轮一行：

```json
{
  "at": 1793570000000,
  "key": "private:xxx",
  "blocks": [
    {"id":"goals","chars":120},
    {"id":"continuity","chars":340,"concernIds":["c1"]},
    {"id":"emotional","chars":90},
    {"id":"memory","chars":800,"memoryIds":["m1","m2"]},
    {"id":"narrative","chars":210,"narrativeId":"20d7d6fb"}
  ],
  "budgetChars": 2200,
  "dropped": ["taste"]
}
```

用途：

- 拾光 →「这一轮用了哪些证据」；
- 回廊 →「这条记忆最近被用过几次」；
- 排查“为什么回复像没看见某条记忆”。

## 4. 分阶段实施

### 阶段 A：可追溯（不改模型，先让引用存在）

1. **新记录严格带来源**：探索抽取兴趣/自我记忆时写入 `episodeId`、`sourceUrl`、`verified`；
2. **旧记录不猜来源**：缺少 `episodeId` 的旧条目一律标 `verified: unknown`，**禁止**用模型回忆补写 episode 或 URL；
3. 拾光每条证据增加「来源」展开：核验等级（逐字 / 转述 / 未核实 / 来源未知）、来源片段、URL、时间、逐字摘录；
4. 回廊每条记忆增加「被引用」计数（从 `broadcast-trace` 统计，阶段 C 后）。

**验收**：先做**基线抽样**（现有记录随机 10 条，人工核对来源是否真实存在），它只描述当前数据质量，**不能据此宣称“整体可追溯”**。阶段 A 的通过标准是：新写入记录 100% 带 `verified`，且 `unknown` 不被伪装成 `verbatim`。

### 阶段 B：巩固与互链

1. 夜间巩固任务：`episode → taste / selfMemory / belief` 的候选关联，写入 `refs`；
2. **关联分两级**：
   - **强证据（可自动确认）**：同一 episode、同一明确 URL；
   - **弱证据（只做候选）**：同一 topic 且时间接近、同一作者/同一视频的不同片段；
3. 弱证据必须展示**命中规则**与**置信度**，默认不进入回复上下文；
4. 拾光显示「相关」：同 topic 的其他证据、同源的挂念；余音显示「相关证据」。

**验收**：抽 10 条关联人工核对，**试点门槛** 8/10 成立即可进入下一阶段，这不是长期质量标准。长期标准：强证据错误率接近 0；弱证据必须带置信度且可关闭。

### 阶段 C：广播 trace

1. 每轮记录 `broadcast-trace`（不存正文），字段至少包括：
   - `at`、`key`、`assemblerVersion`（上下文装配器版本）；
   - 每个 block：`id`、`chars`、对象 `id`、`version` 或 `contentHash`；
   - `dropped`：被丢弃的候选及原因（预算 / 优先级 / 去重）。
2. 拾光新增「这一轮为什么这样回」折叠区：blocks + 被丢弃的候选；
3. 回廊显示“最近被引用”。

**验收**：任意一轮回复能解释“用了哪几条记忆/挂念”；在有对象版本/哈希的前提下，可重建当时选中的条目（不要求重建完整 prompt）；trace 体积 < 2KB/轮。

### 阶段 D：评估联动是否真的有用

1. **预先固定样本**：在评测开始前冻结一组对话（例如 30 段 owner 私聊），不得边跑边挑；
2. **盲评**：把开启/关闭联动的回复打乱顺序，由人按固定问题打分（不告诉评分者哪条是实验组）；
3. **指标定义**：
   - 重复提问率 = 同一会话内，她追问“你之前说过…”且该信息已在上下文中出现过的轮次 / 总轮次；
   - 接上前几天的事 = 回复引用了 3 天前的具体事件且未被当轮提示，人工判定为“是/否”；
   - 错误引用率 = 回复中的具体事实与来源不符的次数 / 引用次数（必须单独统计，不能只看“更连贯”）；
   - 成本 = 每轮输入 token 增量。
4. 结论只有两种：保留、或砍掉不产生增益的联动。

**验收**：如果 D 阶段没有可测增益（连贯性提升不显著，或错误引用率上升），A–C 只保留“可追溯”，不保留“自动关联”。

---

## 4.5 隐私与删除

1. `refs` 与 `broadcast-trace` 都只存 id、哈希、长度，不存正文；
2. 删除一条记忆时：级联删除指向它的 `refs`，trace 中保留 id 但标 `deleted: true`（不保留内容）；
3. `private:<QQ>` 的 refs 和 trace 只能在该 key 的管理视图里看到，群聊和他人不可见；
4. trace 保留 90 天，`refs` 跟随记忆生命周期；
5. 提供导出/删除接口：导出包含 refs，删除按 key 级联，不留下“可反推内容”的片段。

## 5. 与各模块的具体接口

| 模块 | 从拾光拿什么 | 给拾光什么 |
|---|---|---|
| 回廊 | 证据对应的 episode | 记忆被引用次数、最近使用时间 |
| 轮廓 | 无（避免把目标权重当性格） | 慢漂移记录（哪条证据推动了变化） |
| 潮汐 | 探索/叙事被情绪影响的记录（若有） | 当前情绪快照（只读） |
| 余音 | 挂念关联的证据 | 挂念列表与状态 |
| 年轮 | 兴趣 → 学习路径（阶段 B 后） | 课程与作业记录 |
| 目标 | 权重与来源 | 探索动机的当前值 |

---

## 6. 风险与红线

1. **伪科学包装**：不把 GWT/预测加工写成“她因此有意识”；文档与界面都不出现“意识水平”。
2. **假关联**：没有 `refs` 就不画线；宁可空着。
3. **数据膨胀**：trace 只存 id 和长度，不存正文；90 天滚动。
4. **过度拟人**：界面用「证据」「来源」「置信」，不用「她记得很清楚」这类断言。
5. **成本**：阶段 A/B 不增加模型调用；C 只写本地日志；D 才做 A/B 评测。

---

## 7. 建议的下一步

先做 **阶段 A**（给现有记录补 `refs`，拾光可追溯），它不改回复行为、不增加成本，却能立刻回答“这条兴趣/记忆从哪来”。

阶段 B 再决定要不要自动互链；C/D 视 A/B 的效果。
