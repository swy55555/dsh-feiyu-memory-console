# memvec：存储、检索与来源

适用 0.11.1。memvec 是本地 Python 记忆服务，默认回环端口 9881，使用 SQLite、numpy 和 fastembed。首次嵌入模型下载需要网络，缓存后向量化可本地执行；其他聊天／审核模型调用属于不同路径，不能据此宣称整个插件离线。

## 数据不只是一张 memories 表

- `memories` 保存正文、作用域、状态、重要性、保留尺度、向量和来源标识。
- `messages` 保存有身份和时间的原话，具有每会话窗口限制。
- `session_summaries` 保存带覆盖信息与来源的摘要。
- 来源版本、证据链接和修正记录支持跨原话窗口的追溯与撤回。
- 操作与审核回执用于检查依赖版本、复用有效结果和受控撤销。

表与字段的最终定义在 `memvec/server.py`。schema 版本与应用发布版本不是同一个数字，不应为升级应用版本随意修改迁移编号。

## 写入与确认

调用方提供作用域、正文及可核对的来源。服务校验入参、生成向量、处理重复或候选关系，再提交。候选不能仅因文本相似就被当作原话支持；冲突与语义核对有独立流程。

最终确认在事务内重新检查相关版本与集合，防止模型核对期间其他操作改变事实。失败应回滚；收到失败响应不应盲目重试整个业务操作而不检查现有回执。

## 检索与上下文

先按请求作用域、状态、有效期与来源条件过滤，再按向量相似性等因素排序，返回有限结果。不能把历史 global 兼容数据当作跨会话共享所有私人记忆的授权。向量缓存必须随真实数据变化失效，读取缓存本身不强化记忆。

检索结果进入上下文仍受调用方预算、去重和参考规则约束。数据库存储条数、检索返回条数、实际投递条数、模型采用条数是不同概念。

## 保留与归档

普通记忆采用 `R=1/(1+t/S)` 的工程保留函数，详见 [内容保留](content-retention.md)。有效的新来源与时间条件满足后才能加强；打开页面、向量检索、摘要重述与合并不应自增证据。归档退出活动集合，不等于擦除数据库和备份。

## 并发、鉴权与备份

请求使用 `x-memvec-token`；客户端与服务需共享令牌文件或环境配置。不要把令牌写进网页或 URL。单进程锁、SQLite 事务和跨进程锁冲突需要分别处理，不可假定进程内锁能保护另一份 Python 实例。

运行中的数据库可能使用 WAL。应停止写入方后备份完整状态，或使用 SQLite 一致性备份接口；只复制一个正在变化的 `.db` 文件不能保证完整。恢复前核对真实路径，目录联接可能让不同盘符路径指向同一文件。

## 参考与验证

设计依据统一见 [技术手册的论文索引](TECHNICAL_MANUAL.md)。本服务不宣称实现完整 FSRS，也不将工程保留分数解释为人类回忆概率。单元、事务、来源、锁与重启测试不能替代真实语义评估。
