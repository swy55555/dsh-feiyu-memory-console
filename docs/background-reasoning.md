# 后台思考强度与超时取消

适用版本：0.10.0。

## 使用方法

进入“花费”，找到“后台思考强度”。14 个后台模块分别提供低、高、最高三个实际档位。拖动滑块后点击“保存后台档位”，新调用使用新设置，正在运行的调用不会被重启。键盘聚焦滑块后可以用左右方向键调整。保存失败时会保留未保存的选择。

低档不代表没有情绪，也不会减少记忆保留时间；它只调整模型处理这项任务时的推理强度。高档不保证一定正确，低档也不保证每次都更便宜。

| 模块 | 默认值 | 理由 |
|---|---|---|
| 事件理解、情绪复核、空闲联想 | low | 日常、短程判断优先降低推理强度 |
| 记忆提取、提取查漏 | high | 小样本对照未证明降档有稳定收益，继续观察 |
| 确认联合复核、事实复核、候选核对 | high | 联合复核负责自动确认首轮；事实复核用于后续分页和手动核对，候选核对保留兼容旧入口 |
| 聊天摘要、性格整理、性格草案、日记生成、图片理解、其他内部调用 | high | 保守默认，允许分别调整 |

聊天本身继续使用原来的聊天档位，后台设置不改聊天配置。不设每日总调用上限。

## 如何防止误改聊天档位

当前 DSH 的普通 `session/selectModel` 会同时保存全局默认模型。后台改用宿主提供的受令牌保护的专用入口，只允许 `qq-memory` 无工具会话，并只提交该会话下一次请求的模型选择，不保存全局默认。参数不被模型接受、宿主缺少必要能力或控制台未升级时直接报错，不偷偷走旧接口。

这是对当前 DSH 会话控制器的兼容适配，依赖其 `resolveAgent`、`serializeImageAdmission`、`selectForNextRequest` 和模型配置校验能力；未来 DSH 改动接口后需要重新验证。部署必须同时更新控制台宿主代码和桥接运行时。

## 超时的处理

此前停止等待结果之后只归档会话；归档只是隐藏，并不等于停止生成。

现在超时或异常会先移除后台会话尚未处理的输入，再调用取消生成，最后清理订阅与归档。取消失败时保留会话，阻止新后台调用；之后有任务到来时，先重试停止旧任务。提交请求很晚才返回的情况会再次取消，避免取消之后又出现排队生成。

取消不能退回超时前已经消耗的 token，也不能保证供应商在收到取消前不再生成任何 token。独立实测已收到 DSH 的 `turn/end: aborted`，而非仅验证本地计时器结束。

后台会话还会设置固定标题，避免 DSH 为这些短任务额外生成会话标题。测试和诊断不写入用户真实记忆，不向 QQ 发消息。

## 2026-10-30 真实模型小样本验证

模型：`deepseek-account / deepseek-flash`。提取采用同一组合成消息，high、low 各运行两次；另对两档分别执行一次明确遗漏与一次完整覆盖检查，共八次模型请求。

提取消息覆盖多事实、否定、混合主语、引用、假设、条件、玩笑澄清、偏好变化与计划。正常非健康信息的预期事实以及引用、假设、玩笑的排除检查，两档均通过。健康信息是否被标为敏感存在波动；敏感标记导致本地排除，不能误计为模型未提取。这也是当前模型语义判断仍需继续观察的地方。

| 指标 | high | low |
|---|---:|---:|
| 提取平均输出 token | 2,201.5 | 2,437.5 |
| 提取平均耗时 | 10.22 秒 | 12.11 秒 |
| 两次查漏合计输出 token | 145 | 208 |
| 查漏明确遗漏、否定和完整性检查 | 通过 | 通过 |

这些数值只描述本次样本，不是普遍性能结论，也不能推出长期漏记率为零。缓存情况不同，不据此比较单价或承诺节省比例。此次尚无充分依据将记忆提取和查漏默认切成 low，因此保留 high；用户可以在滑块中显式调整。

取消实测：在独立合成会话发出请求后触发短超时，确认调用停止接口并收到 `aborted` 终态。正常 QQ 会话未被取消。模型对照使用的旧接口对全局默认值的临时影响在生成前恢复，并在测试结束后再次核对与原值一致；正式实现使用上述会话隔离入口。
