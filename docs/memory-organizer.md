# 省心整理：把日常维护与模型审核分开

入口：控制台 → 整理 → 省心整理。适用 0.10.1。

阅读、预览、归档并不需要语言模型。确认或恢复记忆时，如果原话支持或历史关系尚未核对完整，原有按钮会补做语义审核，可能产生多次调用。不要用反复点击确认来清理列表。

## 使用方法

1. 选择一个私聊或群聊，点击「本地预览（不调用模型）」。每页最多 50 条，显示该聊天的待整理总数，可翻页。
2. 检查原因，必要时展开原话。所有条目都可以勾选，可「全选本页」或「仅选择建议项」；默认不勾选。
3. 「按建议处理」只执行已满足条件的归档/确认；选中有歧义或缺审核的记录时，这个按钮禁用，但复选框不禁用。
4. 如果你明确不再使用所选记录，选择「主动归档所选」，核对弹窗列出的内容再确认。这个操作不需要模型，也不把候选变成事实。默认保护期及建议条件不会阻止你主动归档；正文、来源和有效期保留，归档后不再参与正常检索。想正式记住的记录应保留待审核。
5. 结果分别列出成功和跳过；到「最近改了什么」可撤销本批修改。

| 分类 | 条件 | 本次模型调用 |
| --- | --- | --- |
| 可归档 | 普通、重要性低于 0.8，明确到期或已确认且充分淡化；迁移保护期已结束 | 0 |
| 可确认 | 完整原话支持及全部当前相关事实的审核已经通过，证据版本仍一致 | 0，复用已有审核 |
| 保留待处理 | 缺审核、缺来源、存在歧义或冲突、仍在保护期等 | 0，不补做付费审核 |

充分淡化沿用现有工程规则：可用程度低于 0.12、距有效加固超过 14 天；不是事实正确率或人类遗忘概率。核心、待办、高重要记忆不纳入建议归档。未过期候选不会因为等待或可用程度低而被归档。

## 边界与撤销

归档只改变状态，不删除正文、原话、期限，不把候选自动变成事实。已有迁移的 14 天保护期仍约束系统建议，包括建议中的过期归档；用户明确选择并确认的主动归档是独立操作。过期记录即使暂未归档，也不会因此重新生效。

预览保留 15 分钟，服务重启后需重新预览；最多缓存 16 份预览。处理时在事务内重新验证记录与审核版本。批内确认前一条可能改变后一条的相关事实；后一条会跳过，不能强行使用旧审核。没有“只看最像的几条就直接确认”的捷径。

同一次请求重试复用结果，不重复执行。整批修改有数据库撤销凭据；后来被修改或出现冲突时会拒绝覆盖后续修改。控制台操作日志写入失败时会明确提示，并显示数据库操作编号供排查。

这里省去的是不必要的维护调用和逐条操作，不能保证所有候选都免费确认。需要语义判断的记录仍可走原来的审核入口；已有自动候选审核开关保持原状。这次没有增加定时模型任务，也没有自动打开付费功能。

这种分工采用确定规则处理状态、语义审核处理不确定事实、保留来源和回滚。它是可检验的工程设计，不宣称模拟了人的记忆整理机制。测试使用本地合成记录，覆盖过期、保护期、缓存失效、跨聊天隔离、重试、分页和撤销，不把模拟记录写入真实记忆。


## 可选审核范围

本版保留默认全量审核，也提供显式开启的相关范围模式：审核选入的同方面事实和少量语义近邻，可能漏掉范围外冲突。页面显示的“审核通过”仅指当前选定范围；原话、有效期和版本检查仍保留。详见[配置与限制](review-scope.md)。此模式不等于所有候选自动生效。
