# 未变化参考复用（试验）

此功能属于下一版源码，未包含在 v0.10.1 已发布资产中。是否生效应以本机安装回执和日志为准。

## 减少什么

桥接原先会在多次投递中附带同一份会话摘要和窗口前聊天原文。新版只对这两类生成的参考块尝试复用。当前用户消息、当前心绪、心绪工作空间、当轮检索结果、完整自我参考与自然表达规则仍照常发送。私聊和群聊沿用同一套人格设计。

复用只省去新投递中的重复文本；上一份参考仍在模型会话里，历史本身并不会因此免费。真实费用还受模型价格、缓存命中、推理输出和每轮工具步骤影响，字符减少不等于 token 或费用同比减少。

## 如何核对

1. 首次发送全文。仅在 DSH 接受且不是命令回复时保存内存回执，回执只含哈希、计数和时间，不持久化原话。
2. 下次发现内容完全一致时，核对桥接已接收的会话事件流及近期 24 条消息边界。不读取历史 HTTP 接口，不新增模型或网络调用；内存只保存序号、事件类型和文本哈希。当前 DSH 不支持早期实现使用的历史接口，早期实现会安全回退为全文，不能据此声称已经省费。
3. 回执按聊天和 DSH 会话隔离。历史中必须存在与完整投递文本哈希一致的 `user/message`，并明确处于追加的模型可见消息面；仅有待处理队列记录不算已进入上下文。
4. 从那条全文消息往后的事件序号必须连续且历史可理解，不能出现压缩或替换。未知必需事件、历史缺失、并发状态失效均恢复全文。长工具回合可能使旧全文落在读取窗口之外，这时不省略。
5. 复用时发送简短沿用标记，保留历史参考与当前纠正优先的边界。每份回执有效十分钟，最多连续复用两次，随后补发全文。参考改变、消失、投递失败或结果不明会重新核对或清除回执。

桥接重启、事件流断开、会话快照及检测到压缩/替换时清除对应回执。新会话没有旧回执。一次投递里出现多份相同文本时不尝试删除，避免误删当前消息。

## 限制与开关

更新桥接后默认尝试。要关闭，在桥接配置设置 `socialV2.context.referenceReuse: false`，通过现有配置保存流程生效；关闭后发送完整参考。此设置尚未增加独立页面按钮。

历史核对与 DSH 随后组装模型请求不是同一个原子操作：核对之后若恰好触发压缩，不能保证本轮仍保留原全文。沿用标记要求不可见时按需检索、不要猜测，事件失效及定期全文补发负责后续恢复。这是节省重复输入的工程试验，不是无损记忆保证。若观察到漏接上下文，应关闭此开关核对。

日志只记录复用类别及减少的字符数，不输出参考原文。此次没有减少工具列表，没有把计时与聊天决策改为本地定时规则，没有另外调用审核模型。

## 验证范围

离线测试覆盖内容变化、跨聊天/会话隔离、重启、排队未消费、压缩替换、未知事件、读取超时、并发失效、失败投递、定期补全和真实发送包装函数。用已有会话做本地回放，四次投递中一次符合复用条件，减少约 1500 字符；其余保留全文。回放没有发送 QQ 消息或调用模型，不能代表安装后的长期节省比例或聊天质量。
