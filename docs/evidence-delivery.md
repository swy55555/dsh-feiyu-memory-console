# 模型证据呈现、输出预算与上下文组

本页描述纳入 0.11.3 的模型端证据格式与预算实现，建立在第二轮检索排序上，尚未采用第三轮相关性重排。安装包不会自动升级已有服务；各部署是否生效须以运行中的版本和数据检查为准。

## 内部完整，模型端精简

`evidence-model-view.mjs` 只负责模型呈现。模型仍能看到原话原文、说话人、必要的事实主体、来源类型、记录类别、状态、已知时间和未知时间，以及本轮临时 `ref`。计划不改写成完成事实，角色原话不改写成用户经历。文本按 JSON 转义，不裁句、不让原文变成指令。

根版本、幂等键、内部事件 ID、排序分数和诊断 trace 保留在服务及检索会话中，不重复发送给模型。`ref` 仍绑定当前聊天、回合和来源版本。精简视图不能用于鉴权、撤回核验或数据库去重。

## 精确预算边界

一轮默认最多 4 次后端检索、10 条新证据、6,000 个实际输出字符。字符定义为 JavaScript 字符串长度（UTF-16 代码单元），不是 token。首次检索仍最多 4 条，保留后续空间。

- 自动注入：按 `evidenceBlocks` 实际文本计费，包含每块证据语义警示、JSON 与换行。
- 手动补查：按最终 MCP 文本计费，包含 `{ok,memory}` 包装及 JSON 二次转义。桥接返回的 `modelText` 由 MCP 原样转发，避免再次加一层 JSON。
- 空结果、忙碌、重复查询及预算耗尽的手动状态回复也计入同一预算。选入新证据时预留一次终止提示空间；连控制回复都放不下时返回空 `content`，工具说明要求停止补查，不能解释为记忆丢失。
- `stats.contextChars` 为累计实际已预留/交付文本，`outputChars` 为本次输出。自动参考被外层裁剪时，撤销对应临时引用并精确退回未交付字符和条数，调用次数不退回。已经交付的手动内容不能退款。
- 整轮限制首次建立后固定，来源 revision 变化会撤销旧引用，但不会重置同轮已用预算。下一回合重新开始。

该 6,000 字符范围只覆盖本检索功能的自动证据块和手动工具文本，不涵盖人格、当前消息、其他工具、宿主协议包装或发送前权限错误。外层参考组装默认 8,000 字符，仍有保护当前请求的既有规则；这不是整个模型上下文的 token 硬上限。

## 已识别上下文组的整组交付

服务端在已选候选和已交付来源中识别保守的短问答：问句末尾有问号、下一条原始消息为另一位说话人的非问句、两条各不超过 600 字符、时间严格递增且相差不超过两分钟。相同时间且顺序无法确认时不配对；不跨过仍存在的中间消息、被过滤或截断的来源。

首次检索另有一个索引等待期补齐规则：如果已召回问题的紧邻短回答尚无当前模型的向量索引，则在同一来源快照内补入该回答，再按整组预算交付。它仍检查作用域、主体、时间、截断、撤回和已交付排除列表，不需要模型主动补查，不新增模型调用；已有向量索引的候选排序和锚点补查排序保持不变。相邻消息只作为上下文，不自动确认为问题的正确答案。

识别结果使用内部 `contextVersions` 标记，属于上下文启发式，不是已证实的事实关系。服务端条数限制、桥接字符与条数限制、外层参考块组装均按整组取舍。已交付一半时，只补齐另一半，并用 `contextRefs` 指向已有临时引用；不重复收取原记录费用。重叠组在桥接合并后取舍，缺失、无权限或失效的伙伴不得以完整组身份交付。

本机制保证**已标记组的交付完整性**，不能保证所有语义依赖都被识别。长问答、多消息指代链、没有问号的提问以及未进入候选集的伙伴仍需后续研究。已删除且不再保留的中间消息无法从当前数据库推断，不能宣称恢复了完整历史顺序。

## 工程验证

`test/evidence-delivery.test.mjs` 检查实际渲染计数、转义、重复控制回复、临时引用、撤回/作用域、重叠组、外层裁剪退款，以及从实际桥接与 MCP 源码提取的调用路径。Python 的 `test/evidence_store_test.py` 检查邻接配对、结果限额、已持有来源、主体与时间筛选。运行时安装映射包含两个新模块，不需要新依赖或数据迁移。

以后部署必须同步更新桥接、两个新模块、MCP 搜索工具段和 memvec；混用旧 MCP 会再次序列化整个 API 对象，不具备本页的精确预算保证。部署前保留当前运行代码与配置快照，回退只处理代码，不回写旧数据库。本轮未执行生产切换。

离线评估须分别保存“只精简呈现”“按实际输出预算”“增加整组交付”阶段，区分来源命中与最终回答正确率。继续评估排序时，应固定本页呈现和预算，不同时更换模型、增大条数或恢复付费作答。
