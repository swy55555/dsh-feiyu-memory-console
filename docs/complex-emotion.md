# 情绪系统 v2：复杂情境与按需模型复核

版本：0.8.10。基于 v0.8.9，整合 preview.1～preview.3 的情绪系统和修复；运行行为与已部署验证的 preview.3 一致。

## 这次采用的方案

使用现有聊天模型做**每日无上限的按需独立复核**。旧配置的 maxPerDay: 3 或其他日次数值不会继续限制调用。模型解释含义，程序负责状态更新、限幅、恢复、身份隔离和事件修正；模型不直接改数据库或任意填写情绪数值。

普通请求、问候等不调用复核。明确冲突、疑似亲昵玩笑、反讽、澄清和部分含糊指代会进入复核候选。复核附带最近最多 8 条同聊天消息、说话人、回复消息 ID、当前角色扮演状态、已说明的忙碌时间和未解决冲突。历史总文本预算约 1,600 字符，每条最多 300 字符，另附当前消息；历史被截短时标记 truncated，提示模型不能把片段当成完整事实。

**保留现有开关与范围。** 原有配置为关闭时，安装不会强行开启。安装后在情绪页面打开“按需复核复杂情境”即可使用；沿用管理员私聊范围。群聊使用说话人隔离和本地情境保护，这一版没有扩大群聊的付费模型调用范围。

## Token 和延迟

普通短消息场景下，每次独立复核粗估额外 **1,000～3,000 token**，包括输入和简短结构化输出；不是实测结果，也不是硬性上限。实际取决于模型分词、系统提示、上下文长度、缓存和推理 token。模型可能误判，不能把协议测试通过当成语义准确率已验证。

| 情况 | 额外消耗预算参考 |
| --- | ---: |
| 未触发复核的普通聊天 | 不产生额外复核调用；仍有正常聊天本身的费用 |
| 1 次复核 | 约 1,000～3,000 token |
| 20 次复核 | 约 20,000～60,000 token |
| 100 次复核 | 约 100,000～300,000 token |

**不设置每日次数或每日 token 上限。** 仍然按需触发，不改成每轮调用。每日计数只用于显示；重启后保留，上海时间午夜重新统计。计数文件异常时也不会因此拒绝复核。默认额外等待 8 秒，可配置 2～15 秒；超时不等于模型没有产生费用。

配置位于桥接现有 `socialV2.emotion.appraisalModel`：

```json
{
  "enabled": true,
  "maxPerDay": null,
  "timeoutMs": 8000
}
```

本版本运行时强制 maxPerDay 为 null，覆盖旧日上限；要关闭模型复核请使用 enabled: false。原 `state/emotion-appraisal-quota.json` 现在只记录当日调用次数。单次上下文限制、超时、去重和结果校验仍保留。未进行在线模型调用，本次没有测得真实 usage；金额需用你的服务实际输入／输出单价分别计算。

## 复杂情境如何处理

- **亲昵玩笑和角色扮演**：像“你这个笨蛋，终于回来啦😂”先保守处理。明确角色扮演状态最多维持 30 分钟或后续 8 条相关消息；“不演了／我是认真的”退出。状态按聊天和说话人隔离。
- **提前说明去忙**：识别明确的忙碌声明，支持部分数字／中文时长；“明天再聊”按上海时间次日上午 9 点，“未说明时长的去忙”默认 4 小时。在有效窗口内不触发主动联系或久未联系小脾气；明确回来或窗口到期后恢复。这里是有限模式识别，不是完整日程理解。
- **没有说明就久未联系**：仍保留原有触发条件和轻微想念、失落、撒娇；不会无限升级成生气。回来说话时缓和，真实冲突单独恢复。
- **澄清误会**：明确说“刚才说的不是你／那句是台词”等，会尝试修正同一说话人、同一聊天最近的一次匹配冲突；引用消息时还要匹配原消息 ID。不是直接把情绪清零，而是从检查点重放后续事件，保留其他人的独立影响。
- **修正边界**：只处理最近 10 分钟、且仍处于最多 16 个事件重放窗口内的匹配事件；底色或人格漂移记录发生外部修改后，不跨越修改回放。窗口外显示“没有匹配事件”，不猜测删除旧历史。
- **派生记录**：被修正事件对应的情景记忆保留原文并标记撤回解释，不再用于情景召回或人格证据；未发送的跨聊天情绪分享被移出队列。已经发出去的话、独立人格事件或历史日记不会被自动撤回。
- **模型不可用**：需要复核的消息先保守处理，不将等待或失败视为确认恶意；页面显示模型已复核、无需复核、结果无效等来源。普通规则路径仍工作。

模型结果仍需通过类型、对象、数值范围和原文证据校验。同一事件只计分一次。新消息、手动重置或人格记录变化后的迟到结果不覆盖当前状态。自动人格记录入口也不再给同一条入站消息额外记一次情绪。

## 安装和回退

使用完整 `dsh-feiyu-memory-console-0.8.10-source.zip` 或同版本 `.tgz`。按源码内 `UPGRADE.md` 维护窗口步骤备份、停止并更新服务；在解压目录运行：

```powershell
node bridge/install-all.mjs --target "D:\your-dsh\qq-bridge" --check
node bridge/install-all.mjs --target "D:\your-dsh\qq-bridge" --apply
```

将示例换成真实桥接目录。新增的 `emotion-context.mjs`、`appraisal-budget.mjs` 会随运行时一起安装、备份和撤销。需正常重启桥接才生效；这是现有 DSH/QQ 桥接的升级包，不包含基础 SDK 或服务环境。

如从原始 v0.8.9 升级，还要按 UPGRADE.md 更新实际运行的 memvec/server.py；如果已完整部署 preview.1，本轮 memvec 无新增修改。默认配置不替你打开原本关闭的模型开关。

撤销本轮运行时：停止桥接后，用本包运行相同命令，将 `--apply` 换成 `--undo`。从预览版升级，会恢复安装前的文件和原回执；继续撤销更早版本时，使用对应旧包安装器。插件前端和 memvec 源码需按自己的旧包备份回退，数据库不会由此命令修改。

- 正式版运行发布回归、浏览器测试以及 v0.8.8/v0.8.9 的隔离升级与回退检查；此前已验证预览版间升级与回退。运行时代码与 preview.3 相同，安装器会将相同文件判为已安装。
- `npm run simulate:emotion` 可复现 8 组离线情景。带“等待复核”场景只演示保守回退，没有冒充真实模型的判断。
- 仍可能漏掉未识别的复杂语气；触发器不是语义理解的保证。模型只处理当前选定范围和有限上下文，不读取无限历史。下一步应在你的实际模型上采样并对照真实 usage 和误判记录，调整触发条件和上下文长度。
