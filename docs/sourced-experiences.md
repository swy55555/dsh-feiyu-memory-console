# 经历分流与本地自动整理

这是下一版源码的功能说明，尚未包含在 v0.10.1 发布资产中。需要同时更新心迹桥接、可塑性记忆控制台与记忆服务；只刷新网页不会完成升级。

## 不需要把每次聊天都确认一遍

“用户在某时说：我今天去看了电影”是一条聊天经历。“用户长期喜欢看电影”是另一个结论。新版分别处理它们，不从一次经历直接推导长期喜好或人格。

普通日常经历，以及完整原话支持的偏好、习惯、计划，仍复用现有提取批次，不新增提取模型。偏好、习惯、计划必须保留整条原话；截取部分句子、缺少限定条件、核心/待办、明确冲突或替换均不走此分流。记忆服务核对聊天、消息编号、实际说话人、原话连续片段及原消息时间，全部匹配后保存为 `memory_kind=experience`。它可正常参与有数量和字符预算的相关检索，提示词会说明：仅证明当时说过，不能证明内容属实、当前仍适用或是长期性格。不会要求用户再点击确认。

敏感信息、明确他人陈述、引用、假设和玩笑仍遵循原提取排除规则。本次没有把每句闲聊全部写成长久记忆，也没有放宽跨聊天共享。短句是否值得保存仍由现有提取器决定，不能保证完全不漏记。

## 旧的待确认会怎样

本地自动整理默认开启，在控制台运行时每分钟轮转一个聊天、扫描最多 50 条，按保存的游标续处理。关闭控制台或停止服务后不运行；重新启动后续处理。开关在“整理 → 自动记忆维护 → 本地自动整理”。旧服务未升级时不执行新流程。

| 内容 | 后台处理 |
| --- | --- |
| 普通日常经历、完整原话的偏好/习惯/计划，有匹配的原始消息，未过期且没有明确冲突标记 | 转为可检索的聊天经历，不再审核为长期事实 |
| 原话及当前审核范围内的关系已完整通过 | 复用已有审核结果确认，不重跑模型 |
| 普通、低重要、已到期或充分淡化的记忆 | 迁移保护期后归档，保留正文和来源 |
| 原始消息缺失、过期、归属不明或判断有歧义 | 保留或按已有到期规则归档；不凭摘要补造证据 |
| 明确冲突、替换已有事实 | 不自动转换或覆盖，继续使用原审核流程 |
| 核心、待办、高重要内容 | 不因普通归档规则被收起 |

“暂存与疑问”不是必须清空的任务列表。没有新依据的内容可以继续暂存。普通经历、偏好、习惯与计划的来源不足时，不会单独消耗候选审核模型；来源随后到达时，下次本地扫描可处理。复杂事实仍可选择开启原有付费审核，或由用户主动核对。此版本没有实现自动在 QQ 发问澄清。

新普通经历不再统一设置七天事实有效期，按已有内容遗忘规则降低检索权重。旧记录的明确有效期原样保留，不因为转换或确认而续期。检索不加固记忆，经历不加入事实关系审核，避免新聊天使已付费审核失效；不拿经历直接填充“已确认个人信息”，也不将不同日期的经历自动合并丢掉来源。

## 查看改动和撤销

后台整理结果会写入“最近改了什么”，可整批撤销。撤销需要记录仍与操作后的版本一致，否则拒绝覆盖后来的修改。撤销后，相同内容不再被自动整理；内容或来源有实质变化才重新评估。仍可手动核对或主动归档。后台运行状态只显示最近 30 批摘要，完整修改记录使用既有审计日志。

手动批量预览、选择和主动归档功能保留。归档仍意味着不参加正常检索，不能用归档代替记住。

## 费用与限制

本地自动整理没有语言模型调用入口。原来的批量提取、独立查漏以及可选复杂事实审核仍可能收费；把这些步骤合在一个页面，不会让它们免费。本次节省的是普通原话记录的后续确认，以及经历新增导致的无关事实复核。

这是一种可测试的来源追踪和事实管理设计，不是对人类记忆机制的完整模拟，也没有用模型自报置信度证明正确率。验证使用合成消息、隔离数据库和模拟向量；实际能分流的数量取决于原始消息是否仍在、来源是否匹配、有效期及冲突状态。
