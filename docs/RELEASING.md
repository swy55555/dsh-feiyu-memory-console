# 发布规范

本项目的发布单位是同一 Git 提交中的插件、桥接运行时、memvec 和文档。正式版使用 `v主.次.修订` 标签，预览版使用 `-preview.N` 后缀并标记为预发布。公开后的标签和附件不可原地改写；修正应发布新版本。

## 发布前

1. 确认工作树中每个改动的来源和范围，检查远端最新提交，不能覆盖他人更新。
2. 同步 package.json、运行时版本、memvec 版本、README、CHANGELOG、UPGRADE 和手册。版本数字必须一致。
3. README 说明项目定位、前置条件、安装、功能、数据流和限制；详细操作放入用户手册。默认值按代码核对，不使用某台机器的配置冒充默认。
4. 手册提供 Markdown 与 PDF；验证中文字体、目录、表格、页码和链接。截图只能用合成数据，并说明版本。
5. 运行 `npm test`、三个浏览器测试（主界面、上下文、花费与联想）、`git diff --check`；对支持的旧运行时验证检查、安装、重复安装和原字节回退。
6. 检查打包清单，排除数据库、模型缓存、账号配置、令牌、真实聊天、日志和备份。安装包应包含当前手册和升级说明。

## 版本与提交

提交全部发布内容，再创建带说明的版本标签。标签必须指向经过验证的提交；不得强推改写已有公开版本。若仓库启用分支保护或 PR 流程，遵循仓库规则，不绕过。

## 必备附件

- `dsh-feiyu-memory-console-X.Y.Z.tgz`：插件包。
- `dsh-feiyu-memory-console-X.Y.Z-source.zip`：从发布提交生成的源码包。
- `USER_GUIDE-X.Y.Z.md` 和对应 PDF：用户手册。
- `UPGRADE-X.Y.Z.md`：升级与回退说明。
- `SHA256SUMS-X.Y.Z.txt`：上述附件的 SHA-256；不包含校验文件自身，避免自引用。

Release 正文说明主要变化、下载区别、升级要求、兼容性、费用变化、测试范围和已知限制。不得把离线协议测试说成模型语义准确率验证，也不得把试验功能写成稳定承诺。

## 公开流程

先创建草稿，绑定明确的发布提交；上传附件并比对名称、大小与 SHA-256，再公开。发布后重新读取标签、发布状态和附件，验证下载内容与本地一致，检查 README 与手册链接。正式发布可以设为 latest；预览版不得替代正式最新版。

失败时保留已上传草稿和记录，重试前检查当前状态，不能盲目新建重复发布或删除用户附件。GitHub Release 与 npm registry 是不同发布目标，本项目的 GitHub 发布不自动执行 npm publish。
