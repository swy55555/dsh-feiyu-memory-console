# 心迹与可塑性记忆：分阶段优化计划

## 目标与固定边界

让系统记得准确、能随澄清修正、少重复处理，用户不用日常逐条确认。自然交流继续保留不同意见、拒绝和各用户不同的相处偏好；不以固定嘴硬、强制温柔或虚构经历证明人格。

- 保留 SQLite、已有记忆、六维性格、完整自然表达规则、共享权限和审计撤销。
- 保留用户自改的语音、唱歌接口与模型配置。安装前重新比较运行文件；使用已知基线合并补丁，不整包覆盖。未知冲突先查明，不强行选取源码版本。
- 不增加默认每轮润色器，不扩大群聊的独立情绪分析调用，不开启新的付费功能。
- 不把待确认清空率当正确率；原话可参考，不等于事实已核实。
- 每项依次经过：代码及数据盘点 → 最小实现 → 隔离测试 → 回归 → 差异安装 → 运行检查。未通过当前项验收，不扩展下一项的行为。
- 执行普通可逆修改不反复要求用户批准。重启若会中断无关任务，则等待任务结束或另行协调。发布作为单独交付动作，不在每个小阶段自动发版。

## 1. 来源与纠正机制

### 当前基线

原话在 `messages`，记忆包含 `scope / subject_id / source_id / source_text / source_time`；摘要另存 `covered_ids`。挂念、认识、自我参考和回应倾向在桥接状态里各自保留证据。现有审核已有内容版本与回执，但这些来源关系尚未统一。

`add_message` 当前按会话保留最近 5,000 条原话，超过数量直接淘汰。部分派生内容存有摘录，但摘录不能替代完整上下文。这是来源保留策略需先解决的问题；不能因此宣称现有记忆已经丢失。

### 子步骤

- **1A 来源盘点与契约**：只读检查数据库及桥接证据，区分来源匹配、原话已不可用、原话版本不一致和缺少可验证标识。缺少来源不自动等于记忆错误。报告仅输出数量，不输出聊天内容或账号。
- **1B 统一来源引用**：以聊天范围、消息编号、说话人、作者类型、完整原话版本建立引用；区分原话、摘要、模型推断、人工编辑。普通重复投递不能伪装成纠正。旧数据可核验才迁移，无法核验标为历史来源不完整。
- **1C 来源保留**：把近期聊天窗口与长期证据保留分开；被记忆或认识引用的原始依据，在近期窗口淘汰时仍可追溯。先评估本地容量和隐私删除语义，不默认无限保存全部聊天。用户删除来源时，相关副本也必须遵循删除要求。
- **1D 影响预览**：纠正前列出直接及间接引用它的记忆、摘要、挂念、回应倾向、自我参考。不能只按消息编号跨聊天查找。
- **1E 纠正联动**：已明确纠正的依据标记旧版本失效；依赖它的结论暂停作为当前依据，保留历史与原因。只重评受影响部分。普通新说法、偏好变化和对旧话的纠正分别处理；语义不确定时保留，不自动覆盖。
- **1F 接入现有交流**：优先复用既有事件理解/记忆提取对明确澄清的判断，再由本地版本和来源检查提交。模型输出不得自行扩大影响范围。没有必要证据时不额外启动“全库纠正”。

**不会做的事**：来源改变后立刻机械撤销全部性格增长或倒退情绪；把机器人自己的旧回复当用户证据；自动用摘要重建已经丢失的原话。

**验收**：同编号跨聊天和跨人物不串用；更正否定与条件能够定位依赖；摘要与模型自述不能升格原始证据；新旧版本并发拒绝过期写入；重复处理不新增支持次数；撤销不覆盖后续修改；原话淘汰与隐私删除分别验证。首次在隔离副本跑，不先改真实库。

**回退**：关闭新联动读取，保留来源历史与现有可用记录；不删除新表来回退，不用整库旧备份覆盖更新后新产生的聊天。

## 2. 统一聊天参考组装

盘点摘要、长期记忆、轻量便签、挂念、认识、情绪解释、自我参考、课程各自的入口与预算。给参考携带来源、版本、用途与授权范围，先生成候选，再统一选择。

同源且同义的内容只保留一份主要表述；情绪反应和事实用途不同，可以保留简短区别，不能因同源而全部删掉。当前原话与明确纠正优先；完整表达规则、工具权限和当前请求不进入普通记忆裁剪。稳定内容保持顺序及序列化一致，动态状态及时刷新，不冻结十轮心情。

**验收**：同一事实不被五个模块重复注入；相关来源和必要条件仍保留；不跨聊天泄露；当前消息无损；总预算边界可解释；模型上下文不可证明保留时仍发送必要全文。使用旧聊天只读回放比较字符、真实 token（可取得时）、误丢信息和回复效果，不拿字符减少比例当费用节省比例。

**回退**：按开关退回原组装路径。不得同时运行两套组装并把两份结果一起注入。

## 3. 后台任务与处理结果复用

现有事实审核已有持久回执；提取与查漏使用的部分 `ReviewMemo` 是 30 分钟内存缓存。先画实际调用表，不新增第二套独立审核链。

统一任务标识：处理目的、聊天/人物范围、来源版本、相关记忆版本、模型及提示/解析版本。不同目的不能只凭同一条原话强行复用。任务保存排队、运行、成功、可重试失败、结果不明、已过期状态；只复用已通过各自校验的成功结果。允许同目的并发等待同一任务结果。

重启恢复时区分“远端可能已经花钱但本地没收到结果”和“请求确定未提交”；结果不明不自动无限重试。错误退避与并发上限保护资源，不设置固定日配额直接扔掉重要原话。手动重试也要显示是否可能新增费用。

**验收**：重启后同版本成功结果可复用；输入、权限、模型或处理版本变化后失效；多人不串；写库失败不重复提取；失败缓存不冒充成功；不会把独立查漏取消成模型自报完成；日志能说明为什么发生第二次调用。

**回退**：停用新调度入口，保留已完成回执；未完成任务只由一个调度器接管，避免旧新同时消费。

## 4. 人物、时间和条件检索

保留现有向量、词面匹配、遗忘权重和预算，在可测案例上补充明确人物、日期区间、事件时间与当前有效版本。普通本地处理优先；不默认每次查询再调用一个重排大模型。

检索结果去重与数据库合并分开。向量接近不足以证明同义；不同日期、不同人物、否定和条件差异不能被去重丢掉。时间不明确不擅自补日期；长期旧事不能因为不在热数据窗口而永远找不到。

**验收案例**：不喜欢煎饼/喜欢小笼包同时可用；以前喜欢/现在不喜欢呈现变化；“周末偶尔喝”不变成“每天喝”；“上周说的事”找到正确事件；群友甲乙观点不混；私密记忆不因高相似分绕过授权。

**回退**：切回原检索策略，保留新增可重建索引，不改记忆正文和事实状态。

## 5. 处理过程与花费解释

扩展已有跟踪，展示“收到 → 提取/跳过 → 存储 → 检索 → 入选参考 → 模型接收 → 实际回复结果”。各阶段记录来源版本、任务标识、选择/拒绝原因，关联已有用量账本。

让用户能区分：未提取、保存为暂存、来源不完整、已过期、未授权、检索未命中、预算未选入、已交给模型但无法证明被使用。页面默认给简明解释，技术字段放在展开详情。

**验收**：每次有记录的额外模型调用能指向处理任务；缓存命中显示零新增调用而非伪造零成本历史；取消/重复/未知用量不重复入账；发送成功不显示为“确实使用了记忆”；查看页面本身不调用模型。

**回退**：新增跟踪为旁路，失败不能阻断聊天或记忆写入。日志要有容量限制，默认不复制整段私人提示词。

## 6. 备份与恢复演练

沿用 SQLite 一致性备份。区分必须备份的原始依据、状态、权限、审计与可重建的索引缓存。备份清单记录版本、校验值和必要文件，不记录明文密钥到公共报告。

在隔离目录恢复，禁用外发消息和付费模型；核对数据库完整性、记录与来源、共享限制、撤销链及抽样检索。索引重建与原始事实恢复分开，重建不额外生成人格和情绪经历。

**验收**：模拟中断/损坏时能报告并保留可用备份；恢复不启动 QQ 外发；只在测试副本执行恢复演练；结果有明确成功/失败报告。自动备份频率、保留容量与自动清理需在实际大小测量后确定。

**回退**：备份/演练独立于聊天；失败保留上一份验证成功的备份，不触碰正在使用的库。

## 暂不引入

多设备云端同步、自建操作日志替代 SQLite、完整知识图谱、固定每日记忆名额、逐条人工追认、纯词表重要性筛选、默认每轮付费润色。只有实际需求和测量结果表明必要时，才另立任务。
