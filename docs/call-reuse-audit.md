# 心迹与可塑性记忆：融合与冗余检查

适用：0.10.1。检查范围是心迹桥接、可塑性记忆控制台及其记忆服务。旧“鱼的记忆”和旧“心情”不在本次修改范围。

2026-10-30 进一步核对了实际请求、长上下文、重试、图片描述与峰谷费用统计，详见 [调用与花费检查](cost-audit-2026-10-30.md)。

## 内容由谁负责

| 内容 | 负责模块 | 与其他模块的边界 |
| --- | --- | --- |
| 当前消息的语境、事件、细微感受 | 心迹连续事件理解 | 同一结果供情绪、挂念、待验证认识和回应反馈使用，各自校验；不直接写为长期事实 |
| 这一刻如何回应 | 本轮关注筛选 | 组合相关记忆、心绪、临时表达要求、回应倾向和联想；本地处理，不额外调用模型 |
| 身份参考与六维倾向 | 自我参考整理 | 共用批量整理调用，按真实原话及多日证据缓慢改变；开启后旧性格整理停止 |
| 用户明确说过的事实与近期便签 | 可塑性记忆提取 | 一次提取返回事实与便签，人物归属、语气、来源和期限分别检查 |
| 是否漏掉原话中的内容 | 独立查漏 | 继续独立核对，不让提取器自己宣布完整就清空队列 |
| 候选是否可确认 | 联合确认审核 | 原话支持与首批历史关系共用调用；后续分页仅核对缺失关系，最终确认仍检查全部回执 |
| 空闲时可聊的话题与模糊感受 | 空闲联想 | 一次生成最多三步短话题链和可选感受；猜测不成为事实、人格证据或主动发送理由 |
| 页面查看、向量检索、来源检查 | 控制台与本地记忆服务 | 普通状态读取不调用聊天模型；向量检索使用本地模型，不计为聊天模型 token |

## 本次消除的重复

### 1. 联想链重复输入

旧流程每一步重新发送原始记忆和规则，最多三次模型调用。步骤之间没有外部工具或新增事实，因此改为一次返回最多三步。程序仍逐步校验来源、去重和停止条件；不要求凑满三步。新消息、权限改变或关闭开关会使旧结果失效。旧格式单节点结果可接受一次，不追加调用补足步数。

冷却、十分钟期限、无来源不调用、相关时才提供给聊天、提供前复核来源、感受衰减和不自动写入事实等边界保留。历史话题现在也传入生成请求，帮助模型避免刚想过的话题；这部分会增加少量输入，实际节省需按总 usage 比较。

### 2. 联合结果的局部失败

过去，一条挂念的 ID 或原话证据不合法，会把同一输出中有效的情绪判断也丢掉，可能再调用情绪模型。本次只有在完整 JSON 可解析、情绪部分单独通过原有校验、当前消息仍有效时，才复用情绪。挂念、认识、关系、回应学习均不更新。界面记录“已复用情绪，其他更新未通过”。

无效情绪、超时、截断 JSON、过时结果不会绕过校验；需要时仍走原有兜底。合并不意味着所有字段一起放宽条件。

### 3. 记忆任务失败重试

提取结果有效，但查漏超时或数据库暂时写不进去时，以前再次提取同一批原话。本次对有效提取和有效查漏分别复用：键包含会话、完整提示词和模型设置，提示词覆盖原话、人物、相关事实、进度及便签上下文。

每个记忆工作器合计最多16项、30分钟，命中不续期，重启清空；只保存于进程内。失败与无进展的提取、不确定查漏不作为成功结果缓存。原话纠正、相关事实改变、模型/思考档位变化、进度改变或跨聊天均重新核对。复用后仍重新执行当前校验、权限检查与写入，不复用写入成功的假设。

这能避免“数据库写失败却再次付费理解原话”，不保证每次重试都命中。已有部分事实成功入库后，相关事实与进度可能变化，此时重新分析是必要的。

### 4. 工具返回重复身份

`qq_get_prompt` 原先在 `role.hint` 和 `persona` 两处重复提供同一份自我参考。现在自我参考在 `role.hint` 保留，`persona` 仅提供剩余情绪与相关经历；普通唤醒仍完整提供自我参考。旧角色模式兼容路径保留。自然表达与防 AI 味规则没有压缩或删除。

## 已有融合与保留的独立步骤

- 事件理解成功时，情绪判断复用同次结果；回应倾向只增加结构化输出，不另起模型调用。
- 近期便签复用记忆提取；六维倾向复用自我参考整理；主观感受复用空闲联想。
- 候选的原话核对与第一批历史关系审核已合并；版本匹配的原话、关系回执继续复用。
- 独立查漏保留：它与提取承担不同检查职责，不能只为少一次调用而改为模型自报完整。
- 聊天摘要保留：它保存上下文，不等于长期事实提取；只有符合轮换条件或手动请求才执行。
- 挂念与近期便签不强行合为一种记录：挂念有暂停/结束语义，便签还覆盖其他私聊和群聊；它们的范围、生命周期和来源验证不同。
- 人格整理不塞进每条事件理解：它需要跨天证据和历史修订，保留低频批处理，避免每条消息都携带完整人格整理上下文。
- 一代群聊的静默摘要投喂仍存在，它会调用模型；本次未将它当作二代当前聊天的重复调用删除。两代兼容调度的进一步迁移需要单独验证消息补入、媒体和失败恢复。

## 节省范围与验收方式

三步联想的调用上限由3次降到1次，是这条分支的变化，不代表整个系统 token 减少三分之二。原本一步就停止的情况，调用数仍为1。事件部分复用与记忆重试复用主要节省异常路径；正常聊天没有因此取消必要理解。

使用隔离合成数据验证：完整/无效/过时事件、联想停止与来源边界、记忆写入失败重试、查漏失败和不确定结果、缓存期限、模型更改与跨聊天隔离。真实模型对照只使用合成记忆，不发送 QQ、不灌入角色经历。长期联想质量和实际聊天是否自然，仍需日常观察。

本次真实模型对照使用 `low`：雨声阅读、面试交通、早餐偏好与否定条件三组有来源情景，加一组无来源情景。旧版共9次调用、16,169 token，新版共3次调用、5,367 token；无来源两边均为0次。样本内总 token 下降约66.8%，包含缓存读取 token，不等于账单降幅或全系统降幅。两版各自生成结果，存在模型随机性；旧版有一次第三步因重复而停止，仍已发生调用。

新版保留原始来源并生成开放话题，没有修改事实库。部分问题仍可能显得泛泛，联想的自然度不能靠调用数证明。这个改动减少重复输入和往返，不能据此宣称人格或理解能力获得了同等提升。
