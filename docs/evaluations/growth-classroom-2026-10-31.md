# 成长课堂首次机制验收

日期：2026-10-31。此记录不是聊天效果的受控实验，也不证明模型已获得某种能力。

## 实际运行

- 本机已安装，控制台、心迹桥接、记忆服务正常响应。原有 250 条记忆未缺失，性格基线和当前值保持不变。
- 使用 `deepseek-flash`、后台 `low`，为“自然说话”课生成一次草案。
- 账本记录一次调用：输入 1,404 token（缓存命中 768，未命中 636），输出 987 token；服务返回的推理 token 为 0，不据此推断模型内部没有推理。总计 2,391 token，不能用这一例估算所有课程的平均花费。
- 对相同课程再次请求生成时复用缓存，尝试数仍为 1，无第二次模型调用。
- 草案没有批准，课程未启用，总开关已关闭；测试没有发送 QQ 消息。

## 暴露出的质量问题

测试场景是“今天忙了一天，终于坐下了”。模型示例包含“先别急着起来，缓几分钟再说”，但生成的理由称“不总结、不给建议”。这存在自我评价与输出不一致，示例也不能仅凭其格式完整就视为自然、合适。

因此保留用户核对步骤，模型自评不控制是否启用。示例不自动写入事实记忆，也不注入每轮聊天。未使用额外模型循环试图修饰本次结果；实际聊天是否改善仍需另行验证。

## 已完成与未完成的验证

39/39 组回归通过，包含 61 项 Python 测试；新增课程缓存的补充断言通过。模拟浏览器测试覆盖创建、开关、单次生成、审批、反馈停用与转义。安装后的浏览器验证覆盖独立入口、默认关闭、待核对草案、移动端无横向溢出、旧审核日志显示“暂未确认”，未发现页面脚本错误。

这些检查验证的是实现与成本控制。尚未进行多用户、未见场景、随机呈现顺序的启用/停用对照，不能声称改善自然度、共情或通用学习能力。后续应按各用户预先定义的标准，检查具体回应、事实准确、是否保留立场，以及是否机械建议，而不是用练习次数或模型自评分作结论。
