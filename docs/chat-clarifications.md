# 聊天澄清联动（1F：近期整句撤回）

本阶段把已有的来源纠正机制接入正常聊天，不增加一个独立审核模型，不新增要求用户逐条确认的队列。2026-11-01 已完成本机差异安装与验收，连续事件理解及此联动均已开启；其他环境以自己的运行配置、安装回执和服务能力 `source-clarification-v1` 为准。

## 如何生效

在“当前心绪”开启连续事件理解后，“复用本轮理解，处理明确的整句澄清”默认随之生效，也可以单独关闭。本次仅接主人私聊，其他私聊与群聊不为此增加分析调用。没有开启事件理解时，不会为澄清单独启动它。

例如此前说“我明天去杭州”，随后明确说明“刚才那句我明天去杭州说错了，整句不算”，同一次事件理解可以给出整句撤回判断。程序再核对本人原话、聊天范围、完整内容、来源版本、处理版本、时间先后，以及有无更新的本人消息，才提交来源暂停。

这不代表模型的高把握分就是真实正确率。模型仍可能误判语义；本地核验限制它可以修改的范围，不能替代语义判断。

## 不需要逐条确认，但也不会强行改

- **整句原本就说错、明确整体撤回**：符合核验条件时自动暂停该来源及已经登记的相关参考。
- **只改其中一点**：不撤回整句，防止把同一句里其他正确内容一起停用。
- **以前是真的、后来变了**：保留原话作为当时的经历，新情况继续走原有记忆处理流程。
- **指代含糊、引用、玩笑、假设、第三人的说法**：不自动撤回。

局部纠正和时间变化尚未在此新建一套定向重评流程；仍由现有提取和事实审核处理，不能宣称任意复杂澄清都已自动解决。不额外发起全库审核，不自动把模型提出的替代说法确认为事实。

## 原话范围

只使用现有近期对话中，过去 45 分钟内同一人的完整原话，最多六条合格候选；截断、内容不一致、作者不符、来源已撤回的记录不作为目标。旧话最多 1,000 字，当前消息仍受现有事件理解长度上限约束。

来源与版本从本地数据库获取，模型只选择已有候选 ID 并引用新旧完整原话，不能自填聊天范围或扩展目标。远期历史、跨聊天、没有可核验来源的旧认识不在本次自动范围内。

复用当前消息已有的原话写入请求，等它完成后再核验，不重复写入。原话未保存成功时跳过此联动；正常事件理解仍继续。

## 去哪里看、怎样撤销

“当前心绪 → 自动澄清记录”显示处理结果，仍生效且版本一致的操作提供 **撤销这次自动澄清**。即使当时尚未形成记忆卡片，也能从这里撤销。此处沿用当前心绪最近事件的保留范围，并非永久完整历史页面。

已经归档的关联记忆，也能在“查看记忆来源”中的来源纠正入口撤销。只有仍与暂停后版本一致的记录自动恢复；后来的编辑、删除和再次纠正保持现状。撤销不回退情绪、关系或性格数值，不清空已经交给模型的旧上下文。

纠正及其原话依据有持久回执，同一条澄清重复投递、重启或用户撤销后，都不会再次执行原操作。回包丢失时可从本地回执核对结果，不重新调用模型或循环提交。不同目标或改变后的请求不能复用同一个回执扩展影响。

## 花费与队列

不新增模型调用，但不是完全没有 token 增量：存在合格候选时，既有事件理解多带一段说明和候选 ID；实际澄清时增加结构化输出。原话已在同一轮近期上下文中，不再额外重复传一份。

后台提取队列遇到已撤回或暂不能核验的来源，会保留该项并暂停提取，避免反复花费。撤销后可继续按原调度处理。正在运行的提取和查漏会在写入前复核；已经发生的模型费用不能退回，也不声称消除了所有并发调用。

## 验证边界

测试使用固定结构化模型输出和隔离数据库，覆盖一次事件理解复用、局部/时间变化不撤回、原话与作者校验、过期结果、事务回滚、持久回执、撤销后不重放、队列暂停和界面撤销。另在真实数据库的隔离副本加入测试对话进行回放，不写真实聊天。

这些测试验证程序行为，尚不构成当前聊天模型的真实语义准确率评测。后续真实使用需观察误判和漏判；不以测试全通过宣称模型必然理解所有隐含表达。

本次 59 组回归通过，最终修改后的重点测试及界面测试通过；新增数据库和桥接测试各 7 项。真实库隔离副本中的模拟澄清完成暂停、撤销与重复处理核验，既有记录未改变。运行验收核对 21 个安装文件、10 个受保护文件、三个服务及网页开关；没有向真实库提交测试澄清，没有真实测试消息外发或语言模型调用。本次未发布新版本。
